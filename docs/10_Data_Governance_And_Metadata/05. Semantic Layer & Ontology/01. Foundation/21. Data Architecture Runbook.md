# Data Architecture Runbook (DA-18)

## Purpose

Operational playbook for **Data Architecture** to extend namespaces, concepts, mappings, federation, and packages for the next domain or NATCO—without redesigning the Control Plane. Deliverable for **DA-18**.

Depends on DA-01…DA-17 foundation docs (see Related).

## When to use this runbook

| Scenario | Start at |
| --- | --- |
| Onboard a new NATCO | §1 Namespaces → §3 Federation |
| Add a new domain / entity set to `global` | §2 Concepts → §4 Mappings |
| Enrich from Collibra / Dataplex | §4 Mappings |
| Bind Marketplace products | §5 Product binds |
| Publish / share a semantic slice | §6 Ossie packages |
| Resolve conflicts | §7 Governance & conflicts |

## Prerequisites (always)

1. [Systems of Record](08.%20Systems%20of%20Record.md) boundaries respected (do not make Ossie / KG / catalogs the meaning SoR).  
2. Namespace slug registered and `active` ([Namespace Registry](09.%20Namespace%20Registry.md)).  
3. Target concepts exist in Registry with correct `status` for the action.  
4. Predicates from the closed [Predicate Catalog](14.%20Predicate%20Catalog.md) only.

## 1. Extend or onboard a namespace

| Step | Action | Artifact |
| --- | --- | --- |
| 1.1 | Choose slug: `global` \| `natco-{iso}` \| `import-{source}` | Never `main` / `enterprise` |
| 1.2 | Register owner, visibility, parent (`global` for NATCO) | Namespace Registry record |
| 1.3 | Set lifecycle `planned` → `active` via Governance | [Governance Engine](17.%20Governance%20Engine.md) |
| 1.4 | Document Collibra vs Dataplex technical SoR for that NATCO | SoR matrix row / NATCO annex |

**Checklist:** owner · steward contact · catalog systems · pilot domain scope.

---

## 2. Add or change concepts

| Step | Action | Notes |
| --- | --- | --- |
| 2.1 | Prefer extend **`global`** if meaning is shared | Avoid NATCO twin by default |
| 2.2 | Draft concept YAML per [Registry Schema](11.%20Semantic%20Registry%20Schema.md) | `status=draft` |
| 2.3 | Place in ontology group / taxonomy facet | [Ontology and Taxonomy](13.%20Ontology%20and%20Taxonomy.md) |
| 2.4 | Submit `draft` → `review` → `approved` | Global COE for `global`; NATCO Data Office for `natco-*` |
| 2.5 | If SID-aligned, annotate `bootstrap_source` / `sid_*` | [TM Forum SID Pilot](10.%20TM%20Forum%20SID%20Pilot%20Slice.md) |

**Breaking change** to approved `global` meaning → COE + NATCO notification SLA ([Governance](17.%20Governance%20Engine.md)).

---

## 3. Federate NATCO → global

| Step | Action | Predicate guide |
| --- | --- | --- |
| 3.1 | Decide if local concept is needed | Else map catalogs straight to `global` |
| 3.2 | Pick primary edge: `sameAs` \| `specializes` \| `implements` \| `extends` | [Federation Rules](16.%20Federation%20Engine%20Rules.md) |
| 3.3 | Create edge `draft` → `approved` | One primary reporting edge (F5) |
| 3.4 | Verify resolve path | NATCO URI → global for cross-NATCO use |
| 3.5 | Remap on global deprecation within SLA | F6 |

**Do not** use `relatedTo` for reporting or hard product gates.

---

## 4. Create mappings (business / technical)

| Step | Business (DA-08) | Technical (DA-09) |
| --- | --- | --- |
| 4.1 | Collibra term approved | Asset exists in Collibra or Dataplex |
| 4.2 | Search Tier A / approved `global` | Prefer entity URI for tables; property for columns |
| 4.3 | Create map row (`mapsTo` / `represents`) | Set `source_system`, grain notes |
| 4.4 | `confidence=asserted`, promote `active` when concept approved | No `suggested` as active |
| 4.5 | If target is NATCO concept used cross-NATCO | Federation required (F1/F2) |

Templates: [Pilot Content Pack](20.%20Pilot%20Content%20Pack.md) · contracts: [Mapping Contracts](15.%20Mapping%20Contracts.md).

---

## 5. Bind Marketplace products

| Step | Global product | NATCO product |
| --- | --- | --- |
| 5.1 | Bind **`global/*` only** | **Required** `global/*` when applicable |
| 5.2 | Optional ports/fields | Optional extra `natco-*/*` |
| 5.3 | Dual-write: `authoritativeDefinitions` + Mapping Engine | Same |
| 5.4 | Soft warn → hard gate (maturity 4+) | Block if global missing when applicable |
| 5.5 | Verify reverse lookup | Concept → products list |

See DA-17 examples in [Pilot Content Pack](20.%20Pilot%20Content%20Pack.md).

---

## 6. Publish Ossie packages

| Step | Action |
| --- | --- |
| 6.1 | Confirm package contents vs [Ossie Package Contract](19.%20Ossie%20Package%20Contract.md) |
| 6.2 | Include only `approved` concepts/edges for released packages |
| 6.3 | SemVer: major = breaking meaning; minor = additive; patch = editorial |
| 6.4 | Lifecycle: `build` → `release_candidate` → `released` |
| 6.5 | Import goes to `import-*` then promote — never silent overwrite of `global` |

Ossie is **exchange only** — not a metadata SoR.

---

## 7. Governance & conflict playbook

| Signal | First response | Escalate to |
| --- | --- | --- |
| Double `sameAs` | Flag; compare definitions | Global COE |
| Competing globals | Reject on review | Global COE |
| Definition drift | Force `specializes`/`extends` or fix prose | Domain steward + COE |
| Missing federation on cross-NATCO bind | Soft warn → hard block | Product owner + DA |
| Catalog vs Control Plane prose clash | Catalog wins prose; meaning URI stays Control Plane | SoR matrix |

Audit every status transition; emit events ([Governance Engine](17.%20Governance%20Engine.md)).

---

## 8. Knowledge Graph expectation

After Registry / Mapping / Federation updates:

1. Materialize nodes/edges per [KG Logical Model](18.%20Knowledge%20Graph%20Logical%20Model.md).  
2. Do **not** edit prose or product definition in the graph.  
3. Use Graph API for reverse lookup / impact — Registry remains meaning SoR.

---

## 9. Minimal “next NATCO” sequence

```text
1. Register natco-{iso} (Namespace Registry)
2. Confirm Collibra (+ Dataplex if used)
3. Map ≥5 business + ≥5 technical to global Tier A (or federate)
4. Add federation edges for any local concepts
5. Bind ≥1 NATCO product with dual-bind
6. Steward promote draft → active after concept approval
7. Optional: export Ossie package for that NATCO slice
```

Copy patterns from [Pilot Content Pack](20.%20Pilot%20Content%20Pack.md) (`natco-de`).

---

## 10. Minimal “next domain” sequence

```text
1. Select SID / domain slice (or invent global entities with COE)
2. Draft groups + entities in Canonical Inventory style
3. Add ontology edges / taxonomy facets
4. Extend Predicate Catalog only if new predicate is unavoidable (COE)
5. Author mapping + product bind templates
6. Update KG logical coverage notes if new node classes needed (rare)
```
