# TM Forum SID Pilot Slice (DA-03)

## Purpose

Select the **TM Forum Information Framework (SID)** subset to seed the `global` namespace for the Semantic Control Plane pilot. Data Architecture deliverable for roadmap task **DA-03**.

Depends on: [Namespace Registry (DA-02)](09.%20Namespace%20Registry.md) · [Systems of Record (DA-01)](08.%20Systems%20of%20Record.md).  
Reference: [TM Forum Information Framework (SID)](https://www.tmforum.org/open-digital-architecture/information-framework-sid/).

## Decision (locked)

| # | Decision |
| --- | --- |
| 1 | Pilot seeds **`global`** from SID — not a NATCO namespace. |
| 2 | Import lands first in **`import-tmforum`** (staging), then promote approved concepts to **`global`** via Governance. |
| 3 | Pilot scope = **Customer + Product + Service** domains (plus Common **Party** needed for Customer). |
| 4 | Prefer SID names and ABE alignment; enterprise synonyms allowed — **do not** invent parallel global concepts for the same SID BE. |
| 5 | Full SID import is **out of scope** for MVP; expand by ABE after pilot success. |
| 6 | Licensing / member access to SID artifacts is a **procurement** prerequisite — Data Architecture owns the *selection*; Legal/Platform own license enablement. |

## SID domains in scope (pilot)

| SID domain | Pilot role |
| --- | --- |
| **Common** | Party / PartyRole foundation |
| **Customer** | Customer, CustomerAccount, related roles |
| **Product** | Product, ProductOffering, ProductSpecification (core) |
| **Service** | CustomerFacingService / Service (core link Product→Service) |

**Explicitly deferred (post-pilot):** Resource, Market & Sales (full), Business Partner (full), Enterprise, deep billing ABEs, full characteristic/value catalogs.

## Candidate concept shortlist (`global`)

Stable `concept_id` = kebab-case; URI = `https://semantics.{enterprise}/ns/global/{concept_id}`.

### Tier A — must approve for pilot

| concept_id | Kind | SID alignment | Notes |
| --- | --- | --- | --- |
| `party` | entity | Common · Party ABE · Party | Individual or organization of interest |
| `party-role` | entity | Common · Party ABE · PartyRole | Role played by a Party |
| `customer` | entity | Customer · Customer Party Roles ABE · Customer | PartyRole subtype — buys / receives products |
| `customer-account` | entity | Customer · CustomerAccount | Commercial account relationship |
| `product` | entity | Product · Product ABE · Product | Offering instance obtained by a PartyRole |
| `product-offering` | entity | Product · ProductOffering | Sellable offering |
| `product-specification` | entity | Product · ProductSpecification | Spec defining product characteristics |
| `customer-facing-service` | entity | Service · CustomerFacingService | Service realizing a Product toward the customer |
| `product-order` | entity | Customer / Product · ProductOrder (core) | Order to acquire products |
| `agreement` | entity | Common / Customer · Agreement (core) | Contractual agreement (minimal pilot attributes) |

### Tier B — shared properties (pilot)

| concept_id | Kind | Applies to | Notes |
| --- | --- | --- | --- |

| `contact-medium` | shared_property / entity* | party-role | Email/phone/address channel (*model as entity if richly structured) |

### Tier C — groups (navigation)

| concept_id | Kind | Contains |
| --- | --- | --- |

## Import procedure (Data Architecture)

```text
1. Obtain licensed SID package (UML / RDF-OWL / vendor export as available)
2. Load into namespace import-tmforum (status=staging)
3. Map SID BE → Tier A/B concept_id (this shortlist)
4. Steward review: definitions, duplicates, naming
5. Governance approve → promote into global (status=approved)
6. Record bootstrap_source=tmforum-sid on each concept + SID qualified name in annotations
7. Export Ossie package for global pilot slice (after DA-14 contract)
```

| Field on concept | Value |
| --- | --- |
| `namespace` | `global` (after promote) |
| `annotations.sid_domain` | e.g. `Customer` |
| `annotations.sid_abe` | e.g. `Customer Party Roles ABE` |
| `annotations.sid_be` | e.g. `Customer` |
| `annotations.sid_version` | e.g. `R20.0` / licensed version used |
| `bootstrap_source` | `tmforum-sid` |

## NATCO expectations after seed

- NATCO concepts **federate** to these global IDs (`sameAs` / `specializes` / …) — they do not redefine Tier A meaning.
- Collibra terms map preferentially to Tier A global concepts before creating NATCO-only concepts.
- Marketplace Global products bind only to `global/*` from this slice (+ later extensions).

## Out of scope

- Implementing connector code for SID import  
- Full SID coverage or continuous SID sync in MVP  
- Changing TM Forum IP / redistribution terms
