# Semantic Registry Schema (DA-04)

## Purpose

Define the **Semantic Registry** concept schema for the Control Plane: kinds, attributes, lifecycle, URI/identity, and versioning. Data Architecture deliverable for roadmap task **DA-04**.

Depends on: [Systems of Record (DA-01)](08.%20Systems%20of%20Record.md) · [Namespace Registry (DA-02)](09.%20Namespace%20Registry.md).  
Inventory narrative: [Concepts](../04.%20Enterprise%20Semantics/02.%20Concepts.md) · [Canonical Entities](../04.%20Enterprise%20Semantics/01.%20Canonical%20Entities.md).  
Pilot seed: [TM Forum SID Pilot Slice (DA-03)](10.%20TM%20Forum%20SID%20Pilot%20Slice.md).

## Decision (locked)

| # | Decision |
| --- | --- |
| 1 | Every unit of enterprise meaning is a **Concept** record in the Semantic Registry. |
| 2 | Canonical entities are Concepts with `kind=entity` (no separate SoR). |
| 3 | `concept_id` is stable within a namespace; **URI never changes**. |
| 4 | Lifecycle: `draft` → `review` → `approved` → `deprecated` (Governance Engine). |
| 5 | Only `approved` concepts are valid mapping / product-binding targets (API default). |
| 6 | Schema is namespace-scoped; federation edges are separate objects (Federation Engine). |

## Concept kinds

| kind | Description | Example |
| --- | --- | --- |
| `entity` | Business object / class | `customer`, `product` |
| `shared_property` | Reusable property | `external-identifier` |
| `inline_property` | Property owned only by parent entity | `customer.loyalty-tier-local` |
| `metric` | Measure with semantics | `mrr` |
| `group` | Navigation / subject-area container | `group-customer` |
| `value` | Enum / controlled vocabulary member | `order-status.completed` |

## Identity and URI

| Field | Rule |
| --- | --- |
| `concept_id` | Kebab-case `[a-z][a-z0-9-]*`; unique **within** `namespace` |
| `uri` | `https://semantics.{enterprise}/ns/{namespace}/{concept_id}` |
| Opacity | IDs are stable tokens; labels may change without changing ID |
| Collision | Same `concept_id` in two namespaces = different concepts (link via federation) |

```text
https://semantics.{enterprise}/ns/global/customer
https://semantics.{enterprise}/ns/natco-de/kunde
```

## Core schema (all kinds)

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `concept_id` | string | yes | Stable id within namespace |
| `uri` | IRI | yes | Derived or stored; immutable |
| `namespace` | slug | yes | FK → Namespace Registry |
| `kind` | enum | yes | See kinds |
| `preferred_label` | string | yes | Primary display name |
| `description` | text | yes | Business definition (canonical for Control Plane) |
| `status` | enum | yes | `draft` \| `review` \| `approved` \| `deprecated` |
| `version` | int | yes | Monotonic per concept; bump on material change |
| `effective_from` | datetime | yes | When this version became active |
| `owner` | string | yes | Org / team |
| `steward` | string | yes | Role or group |
| `created_at` / `updated_at` | datetime | yes | Audit |
| `created_by` / `updated_by` | string | yes | Actor |
| `synonyms` | string[] | no | Search aliases (not alternate truths) |
| `labels` | map locale→string | no | Multilingual labels |
| `group_id` | concept_id | no | Parent `group` concept |
| `parent_concept_uri` | IRI | no | Specialization within same namespace |
| `definition_ref` | URI | no | Pointer to catalog/modeling doc (do not fork as master) |
| `classification` | string[] | no | e.g. `PII`, `confidential` |
| `tags` | string[] | no | Free tags |
| `annotations` | map | no | Extensible (e.g. `sid_be`, `sid_abe`) |
| `bootstrap_source` | string | no | e.g. `tmforum-sid`, `collibra` |
| `scope` | enum | no | `enterprise` \| `natco` (default by namespace) |
| `replaced_by` | IRI | if deprecated | Successor concept |
| `deprecation_reason` | text | if deprecated | Why |

## Kind-specific fields

### entity

| Field | Required | Description |
| --- | --- | --- |
| `identity_keys` | yes | Logical business keys for instances |
| `properties` | no | List of inline or `ref` to `shared_property` |

### shared_property / inline_property

| Field | Required | Description |
| --- | --- | --- |
| `data_type` | yes | string, integer, boolean, date, datetime, decimal, enum, … |
| `parent_entity_uri` | yes if inline | Owning entity |
| `enums` | if enum | List of `value` concept URIs or literals |
| `pattern` / `examples` | no | Constraints / samples |
| `unit` | no | For quantities |

### metric

| Field | Required | Description |
| --- | --- | --- |
| `unit` | yes | Unit of measure |
| `better_when` | no | `higher` \| `lower` |
| `formula` | no | Expression or ref to Metrics Layer |
| `grain` | no | Measurement grain |
| `measures_concept_uri` | no | Entity/property measured |

### group

| Field | Required | Description |
| --- | --- | --- |
| `member_concept_ids` | no | Contained concepts (or inverse via `group_id`) |

### value

| Field | Required | Description |
| --- | --- | --- |
| `enum_of` | yes | Property or enum set URI |
| `code` | yes | Machine code |
| `sort_order` | no | Display order |

## Lifecycle

```text
draft → review → approved → deprecated
         ↘ reject → draft
```

| Status | API default | Mappings / product binds |
| --- | --- | --- |
| `draft` | Hidden | Forbidden |
| `review` | Steward-only | Forbidden |
| `approved` | Returned | Allowed |
| `deprecated` | Resolvable by URI | **New** binds forbidden; existing warn → migrate |

Versioning: bump `version` + set `effective_from` on approved material changes; prefer deprecate + `replaced_by` over silent redefine of meaning.

## Example record (YAML)

```yaml
concept_id: customer
uri: https://semantics.example.com/ns/global/customer
namespace: global
kind: entity
preferred_label: Customer
description: >
  A PartyRole that buys products from the enterprise or receives
  free offers or products (TM Forum SID aligned).
status: approved
version: 1
effective_from: "2026-07-22T00:00:00Z"
owner: global-semantic-council
steward: global-customer-stewards
identity_keys: [customer_id]
group_id: group-customer
bootstrap_source: tmforum-sid
annotations:
  sid_domain: Customer
  sid_abe: Customer Party Roles ABE
  sid_be: Customer
  sid_version: R20.0
synonyms: [Client, Abonent]
classification: []
```

## Relationship to other engines

| Engine | Uses schema how |
| --- | --- |
| Namespace Registry | Validates `namespace` slug |
| Mapping Engine | `target_uri` must reference Registry concept |
| Federation Engine | Edges between concept URIs across namespaces |
| Governance Engine | Owns status transitions |
| Knowledge Graph | Nodes keyed by concept URI |
| Ossie export | Serializes approved concepts per namespace |
| Marketplace | `authoritativeDefinitions.url` → concept URI |

## Validation rules (v1)

1. `concept_id` unique per `namespace`  
2. `uri` matches URI template for that namespace + id  
3. `kind` valid enum  
4. `deprecated` ⇒ `replaced_by` recommended (required if successor exists)  
5. `inline_property` ⇒ `parent_entity_uri` required  
6. `metric` ⇒ `unit` required  
7. Status transition only via Governance (no silent `draft`→`approved`)
