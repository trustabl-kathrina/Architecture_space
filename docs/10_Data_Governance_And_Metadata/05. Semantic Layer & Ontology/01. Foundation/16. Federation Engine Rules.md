# Federation Engine Rules (DA-11)

## Purpose

Define how the **Federation Engine** aligns NATCO (and import) concepts to **`global`**: predicates, mandatory rules, conflict detection, harmonization, and product implications. Data Architecture deliverable for **DA-11**.

Depends on: [Namespace Registry](09.%20Namespace%20Registry.md) · [Predicate Catalog](14.%20Predicate%20Catalog.md) · [Multi-NATCO Federation](07.%20Multi-NATCO%20Federation.md) · [Systems of Record](08.%20Systems%20of%20Record.md).

## Decision (locked)

| # | Decision |
| --- | --- |
| 1 | Federation edges are **directed**: typically `natco-*` / `import-*` → `global`. |
| 2 | Cross-NATCO reporting and Global Marketplace products resolve **global** meaning first. |
| 3 | Concepts used in cross-NATCO reporting **must** have an approved federation edge to `global`. |
| 4 | Purely local concepts may omit federation (`scope=natco`) — they are invisible to enterprise-wide consumers by default. |
| 5 | Federation Engine detects conflicts; **Global COE** adjudicates; NATCOs do not silently redefine `global`. |
| 6 | Allowed predicates (closed): `sameAs`, `specializes`, `implements`, `extends`; `relatedTo` is weak and insufficient for reporting. |

## Predicate selection guide

| Predicate | Use when | Do not use when |
| --- | --- | --- |
| `sameAs` | Same business meaning; only label/synonym differs | Local subtype or extra attributes change meaning |
| `specializes` | NATCO is a stricter subtype of global | Full equivalence (use `sameAs`) |
| `implements` | Local operationalization of an abstract global | Claiming identity with global |
| `extends` | Adds NATCO-only properties; core meaning unchanged | Changing core definition of global |
| `relatedTo` | Soft association / navigation | Any cross-NATCO metric or product bind |

## Mandatory federation rules

| # | Rule |
| --- | --- |
| F1 | If a NATCO concept is target of an **active** product bind used outside that NATCO → federation edge to `global` **required**. |
| F2 | If a Collibra term `mapsTo` a NATCO concept and that meaning is shared → prefer map to `global` **or** federate NATCO→global before activate. |
| F3 | Technical `represents` for shared entities should prefer `global` URI; if NATCO URI used, F1 applies when productized cross-NATCO. |
| F4 | `import-*` concepts promote to `global` or `natco-*` via Governance; until promote, no federation as production. |
| F5 | At most **one** primary federation edge per NATCO concept for reporting (`sameAs` or `specializes` preferred). Additional `extends`/`implements` allowed as secondary with documentation. |
| F6 | Deprecated global target → federation edge must be remapped or deprecated within SLA. |

## Edge lifecycle

```text
draft → review → approved → deprecated
```

| Status | Behavior |
| --- | --- |
| `draft` | Steward work; not used by Marketplace hard gates |
| `review` | NATCO + Global steward visibility |
| `approved` | Valid for resolve / expand / reporting |
| `deprecated` | Kept for history; new binds blocked |

Edge schema: see [Predicate Catalog](14.%20Predicate%20Catalog.md) edge instance fields; `predicate` ∈ federation set.

## Conflict detection

| Conflict type | Signal | Default handling |
| --- | --- | --- |
| **Double sameAs** | Two NATCO concepts `sameAs` same global with incompatible definitions | Flag; Global COE picks; losers `specializes` or deprecate |
| **Competing globals** | One NATCO concept `sameAs` two different globals | Forbidden; reject on review |
| **Definition drift** | NATCO description materially contradicts global | Require `specializes`/`extends` or fix prose; block `sameAs` |
| **Missing federation** | Cross-NATCO product bind to NATCO-only concept | Soft warn → hard block (with product gates) |
| **Orphan after deprecate** | Global deprecated; NATCO edge still active | Auto-flag; remap SLA |

## Harmonization playbook

```text
1. Detect conflict (engine rule or steward report)
2. Classify: missing edge | wrong predicate | definition drift | duplicate
3. Propose: remap predicate, merge NATCO concepts, or extend global
4. If global meaning change needed → Governance change request on global (COE)
5. Approve federation edge; emit federation.edge.changed
6. Notify Marketplace / mapping owners if product binds affected
```

## Resolve algorithm (runtime)

For consumer asking “enterprise meaning of X”:

```text
IF X.namespace == global AND X.status == approved → return X
IF X has approved federation edge to G (sameAs|specializes|implements|extends)
   → return G as primary; X as local context
IF X.scope == natco AND no edge
   → return X only to NATCO-scoped callers; else “not enterprise-comparable”
```

## Product implications

| Product | Federation impact |
| --- | --- |
| Global product | Binds only `global/*` — no federation edge required on product |
| NATCO product | Must bind `global/*` when applicable (DA-10); local concept binds should be federated if that local concept is used for shared meaning |

| Activity | R | A | C | I |

| Propose NATCO→global edge | NATCO steward | NATCO Data Office | Global steward | Marketplace |
| Approve `sameAs` / `specializes` | Global steward | Global COE | Data Architecture | Platform |
| Conflict adjudication | Data Architecture | Global COE | Both stewards | All NATCOs affected |
| Engine rules change | Data Architecture | Global COE | Platform | Stewards |
