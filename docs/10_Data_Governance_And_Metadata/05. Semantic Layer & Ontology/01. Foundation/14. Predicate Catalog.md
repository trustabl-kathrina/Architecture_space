# Predicate Catalog (DA-07)

## Purpose

Publish the **controlled vocabulary of predicates** (typed edges) for Mapping, Federation, Ontology, and Knowledge Graph. Data Architecture deliverable for **DA-07**.

Complements: [Semantic Relationships](../04.%20Enterprise%20Semantics/04.%20Semantic%20Relationships.md) (narrative).  
Uses: [Ontology and Taxonomy (DA-06)](13.%20Ontology%20and%20Taxonomy.md) · [Multi-NATCO Federation](07.%20Multi-NATCO%20Federation.md).

## Decision (locked)

| # | Decision |
| --- | --- |
| 1 | Predicates are a **closed vocabulary** in v1 — new predicates require Data Architecture + COE approval. |
| 2 | Every edge instance has: predicate, source URI, target URI, status, owner, version, effective_from. |
| 3 | Federation predicates are **only** NATCO→global (or import→global) for meaning alignment. |
| 4 | Mapping predicates connect **external** identifiers to Registry concepts. |
| 5 | Ontology predicates connect **concepts to concepts** within or across namespaces (business meaning). |

## Edge instance schema

| Field | Required | Description |
| --- | --- | --- |
| `edge_id` | yes | Stable id |
| `predicate` | yes | From this catalog |
| `source_uri` | yes | From node |
| `target_uri` | yes | To node |
| `source_kind` / `target_kind` | yes | Concept, TechnicalAsset, BusinessTerm, DataProduct, … |
| `cardinality` | yes | Declared on predicate type; instance may note actual |
| `inverse_predicate` | no | If modeled |

| `version` | yes | Monotonic |
| `effective_from` | yes | Active-from |
| `namespace_context` | no | Owning NS when relevant |
| `annotations` | no | Extensible |

## B. Federation predicates (NATCO → global)

| Predicate | From → To | When to use | Forbidden |
| --- | --- | --- | --- |
| `sameAs` | natco concept → global concept | Same business meaning; local label only | Redefining global definition |
| `specializes` | natco → global | Stricter local subtype | Weak “related” misuse |
| `implements` | natco → global | Local operationalization of abstract global | Replacing global |
| `extends` | natco → global | Adds local attributes; keeps global core | Silent fork of core meaning |
| `relatedTo` | either | Weak association | Default for cross-NATCO reporting |

**Rule:** Concepts used in cross-NATCO reporting **must** have an approved federation edge to `global` (`sameAs` or `specializes` preferred).

## Disambiguation

| Predicate | Ontology | Federation | Mapping |
| --- | --- | --- | --- |
| `specializes` | Within/across concepts (e.g. Customer→PartyRole) | NATCO→global subtype | — |
| `implements` | — | NATCO operationalizes global | Product implements concept |
| `owns` | Customer owns Account | — | — |
| `ownedBy` | — | — | Asset owned by team (context) |

Prefer **qualified documentation** in `annotations.usage` when the same English word appears in two families.

## Governance

| Change | Approval |
| --- | --- |
| Add predicate to catalog | Data Architecture + COE |
| New edge instance (ontology) | Domain steward → review → approved |
| Federation edge | NATCO steward + Global steward if disputed |
| Mapping edge | Domain steward; confidence scored |

Status lifecycle for edges matches concepts: `draft` → `review` → `approved` → `deprecated`.
