# Ossie Package Contract (DA-14)

## Purpose

Define **what goes into an Apache OSSIE package**, versioning, naming, validation gates, and import/export boundaries. Data Architecture deliverable for **DA-14**.

Depends on: [Governance Engine](17.%20Governance%20Engine.md) · [Ontology and Taxonomy](13.%20Ontology%20and%20Taxonomy.md) · [Systems of Record](08.%20Systems%20of%20Record.md).  
Background: [Apache Ossie](../02.%20Ontology/08.%20Apache%20Ossie.md) · [Ontology Lifecycle](../05.%20Enterprise%20Mapping/04.%20Ontology%20Lifecycle.md).

## Decision (locked)

| # | Decision |
| --- | --- |
| 1 | OSSIE is **exchange only** — never the SoR for enterprise meaning. |
| 2 | One **primary package per namespace** (`global`, each `natco-*`); optional combined “enterprise bundle” for partners. |
| 3 | Export includes only **`approved`** concepts and **`approved`** ontology/federation edges (no draft). |
| 4 | Versioning: package SemVer `MAJOR.MINOR.PATCH`; element URIs remain stable. |
| 5 | Import always lands in **`import-*` staging** (or review queue) — never silent overwrite of `global`. |
| 6 | Mapping crosswalks to Collibra/Dataplex/Marketplace are **optional annex**; not required in core Ossie model package. |

## Package identity

| Field | Rule |
| --- | --- |
| `package_id` | `{org}.semantics.{namespace}` |
| `file_name` | `semantics-{namespace}-{semver}.ossie.yaml` (or `.json`) |
| `namespace` | Exact Namespace Registry slug |
| `semver` | `MAJOR.MINOR.PATCH` |
| `created_at` | UTC |
| `created_by` | Release actor / pipeline |
| `content_hash` | SHA-256 of payload |
| `schema_version` | Ossie / enterprise profile version |

Example: `semantics-global-1.0.0.ossie.yaml`

## Package contents (core)

| Section | Required | Content |
| --- | --- | --- |
| `manifest` | yes | package_id, namespace, semver, hashes, timestamps |
| `namespace` | yes | slug, display_name, kind, visibility summary |
| `concepts` | yes | Approved concepts (entities, groups, properties, metrics, values in scope) |
| `relationships` | yes | Approved ontology edges among those concepts |
| `federation` | if natco / if exporting alignment | Approved NATCO→global edges (when package is natco or bundle) |
| `annotations` | no | sid_* bootstrap metadata |
| `changelog` | yes for MAJOR/MINOR | Human-readable delta |

### Concept projection fields (minimum)

`concept_id`, `uri`, `kind`, `preferred_label`, `description`, `status=approved`, `version`, `effective_from`, `synonyms`, `group_id`, `identity_keys` (entities), kind-specific fields, `annotations` (incl. SID).

### Explicitly excluded from core package

| Excluded | Why |
| --- | --- |
| Draft / review concepts | Not consumable |
| Collibra term prose as master | Catalog SoR |
| Marketplace product records | Marketplace SoR |
| Full technical asset inventory | Catalog SoR |
| Runtime access policies / IAM | Security plane |
| Neo4j physical dump | Implementation detail |

### Optional annex (separate artifact)

`mappings-annex-{namespace}-{semver}.yaml` — business/technical/product mapping rows for partner sync. Versioned independently; not a substitute for Mapping Engine SoR.

## SemVer rules

| Bump | When |
| --- | --- |
| **PATCH** | Label/typo/doc fixes; no URI add/remove; no meaning change |
| **MINOR** | Additive approved concepts/edges; non-breaking |
| **MAJOR** | Removed concepts, changed meaning of approved element, incompatible edge set — prefer deprecate+`replaced_by` in Registry first |

Consumers pin `semver` or “latest MINOR within MAJOR”.

## Export process

```text
1. Select namespace + approved concept/edge set (Governance)
2. Build package + content_hash
3. Validate against Apache Ossie schema (+ enterprise profile checks)
4. release_candidate → steward/COE review (global: COE)
5. Mark released; previous released → superseded (still downloadable)
6. Emit ossie.released; store in object storage
7. Optional: converters for BI/dbt
```

## Import process

```text
1. Receive partner/NATCO/tool package
2. Validate schema + hash
3. Load into import-{source} namespace (staging) OR review queue
4. Steward maps/promotes concepts into global or natco-* via Governance
5. Federation edges created as needed (DA-11)
6. Never auto-merge into approved global
```

## Validation checklist

| Check | Gate |
| --- | --- |
| Ossie schema valid | Hard |
| All concept URIs in namespace | Hard |
| No draft status in payload | Hard |
| All relationship endpoints present | Hard |
| SemVer monotonic vs last released | Hard |
| content_hash matches | Hard |
| Changelog present for MINOR/MAJOR | Soft→Hard |
