# Governance Engine (DA-12)

## Purpose

Define **semantic governance** for the Control Plane: object lifecycles, state transitions, RACI, policies, audit, and notifications. Data Architecture deliverable for **DA-12**.

Depends on: [Semantic Registry Schema](11.%20Semantic%20Registry%20Schema.md) · [Systems of Record](08.%20Systems%20of%20Record.md).  
Package release: [Ontology Lifecycle](../05.%20Enterprise%20Mapping/04.%20Ontology%20Lifecycle.md).

## Decision (locked)

| # | Decision |
| --- | --- |
| 1 | Governance Engine owns **status transitions** for concepts, edges (ontology/federation/mapping), and namespace metadata — not catalog term approval (Collibra) or product lifecycle (Marketplace). |
| 2 | Concept path: `draft` → `review` → `approved` → `deprecated` (reject → `draft`). |
| 3 | Only `approved` concepts are valid targets for **active** mappings and hard product gates. |
| 4 | Breaking change to approved `global` meaning requires COE approval + NATCO notification SLA. |
| 5 | All transitions are **audited** (who, when, from→to, comment) and emit events. |
| 6 | Ossie package release is a **separate** lifecycle (`build` → `release_candidate` → `released`) gated on approved content. |

## Governed object types

| Object | States | Accountable |
| --- | --- | --- |
| Concept | draft / review / approved / deprecated | Global COE or NATCO Data Office (by namespace) |
| Ontology / federation / mapping edge | draft / review / approved / deprecated | Per engine RACI |
| Namespace | planned / active / frozen / retired | See [Namespace Registry](09.%20Namespace%20Registry.md) |
| Ossie package | build / RC / released / superseded | Data Architecture + COE for `global` |

## Concept state machine

```text
        ┌──────────────┐
        │    draft     │◄──────────────┐
        └──────┬───────┘               │
               │ submit                │ reject / withdraw
               ▼                       │
        ┌──────────────┐               │
        │   review     │───────────────┘
        └──────┬───────┘
               │ approve
               ▼
        ┌──────────────┐
        │  approved    │
        └──────┬───────┘
               │ deprecate (+ replaced_by)
               ▼
        ┌──────────────┐
        │ deprecated   │
        └──────────────┘
```

| Transition | Who may initiate | Who may complete | Guards |
| --- | --- | --- | --- |
| draft → review | Steward | — | Required fields valid; namespace active |
| review → approved | — | Approver (see RACI) | No open conflicts; SID annotations if tmforum-sourced |
| review → draft | Approver or submitter | — | Comment required |
| approved → deprecated | Steward | Approver | `replaced_by` if successor exists; impact report |
| approved → approved (new version) | Steward | Approver | Material change → bump `version`; prefer deprecate for meaning change |

## Edge state machine

Same four statuses. Mapping edges: `active` in Mapping Contracts ≡ `approved` here (normalize to `approved` in Control Plane; Marketplace may show “active”).

| Transition | Guard |
| --- | --- |
| → approved | Endpoints exist; target concept `approved` for mapping/product edges; federation predicate allowed |

## RACI

### Concepts in `global`

| Activity | R | A | C | I |
| --- | --- | --- | --- | --- |
| Draft / edit | Domain steward / Data Architecture | Global COE | Other domain stewards | NATCO stewards |
| Approve | Global steward | Global COE | Data Architecture | Marketplace, Platform |
| Deprecate | Data Architecture | Global COE | NATCO stewards | All consumers |
| Emergency freeze | Platform + DA | Global COE | — | All |

### Concepts in `natco-*`

| Activity | R | A | C | I |
| --- | --- | --- | --- | --- |
| Draft / edit | NATCO steward | NATCO Data Office | Data Architecture | Global (if federated) |
| Approve | NATCO steward lead | NATCO Data Office | Global steward if federation | Marketplace (NATCO) |
| Federation approve | See [Federation Engine Rules](16.%20Federation%20Engine%20Rules.md) | Global COE for `sameAs` disputes | — | — |

### Mappings

| Activity | R | A | C | I |
| --- | --- | --- | --- | --- |
| Business / technical map | Domain / NATCO steward | Same | Catalog owner | Platform |
| Product bind | Product owner | Product owner + steward confirm | Control Plane | Consumers |

## Policies (v1)

| Policy ID | Statement |
| --- | --- |
| POL-SEM-01 | No silent edit of `approved` definition text without version bump + review |
| POL-SEM-02 | New active mapping / product bind requires `approved` target |
| POL-SEM-03 | Deprecated targets block **new** binds; existing soft-warn then hard on next certify |
| POL-SEM-04 | Global breaking change → notify all NATCO steward groups within **5 business days** |
| POL-SEM-05 | Suggested (`confidence=suggested`) mappings never auto-approve |
| POL-SEM-06 | Ossie release only from `approved` concept/edge set for that package slice |

## Audit record

| Field | Description |
| --- | --- |
| `audit_id` | Stable id |
| `object_type` / `object_uri` | What changed |
| `action` | create / update / transition / deprecate |
| `from_status` / `to_status` | If transition |
| `actor` | User / system |
| `timestamp` | UTC |
| `comment` | Required on reject / deprecate |
| `correlation_id` | Optional change request id |

Retention: per enterprise audit policy (minimum: life of URI + N years).

## Events emitted

| Event | When |
| --- | --- |
| `concept.submitted` | draft → review |
| `concept.approved` | → approved |
| `concept.deprecated` | → deprecated |
| `concept.rejected` | review → draft |
| `mapping.activated` / `mapping.deprecated` | Mapping status change |
| `federation.edge.changed` | Federation edge change |
| `governance.policy.violated` | Gate blocked an action |

Consumers: Marketplace gates, search index, Ossie rebuild, stewards.

## Notification SLA

| Trigger | Notify | SLA |
| --- | --- | --- |
| Global concept deprecated | NATCO stewards + product owners with binds | 5 business days before hard gate (if planned) |
| Federation conflict opened | Both stewards + COE | 2 business days |
| Mapping target deprecated | Mapping owner | 5 business days to remap |

## Relationship to Marketplace & catalogs

| System | Governance boundary |
| --- | --- |
| Collibra | Owns term approval workflow; does not approve Registry concepts |
| Marketplace | Owns product status; consumes concept status for semantic gates |
| Control Plane Governance | Owns meaning approval |
