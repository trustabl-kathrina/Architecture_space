# Concepts

## Purpose

Define the maintainable inventory for **semantic concepts** in the **Semantic Control Plane** (Semantic Registry)—aligned with Marketplace [Entropy Semantics](../02.%20Ontology/09.%20Entropy%20Semantics.md) UX and published via **Apache Ossie**.

**Canonical schema (DA-04):** [Semantic Registry Schema](../01.%20Foundation/11.%20Semantic%20Registry%20Schema.md).  
**Pilot seed (DA-03):** [TM Forum SID Pilot Slice](../01.%20Foundation/10.%20TM%20Forum%20SID%20Pilot%20Slice.md).

## Scope

| In scope | Out of scope |
| --- | --- |
| Concept kinds, attributes, statuses, namespace rules | Metric formula authoring detail (Modeling Metrics Layer / Entropy metric formulas) |
| Linkage to glossary terms, products, contracts | Inference / reasoning (deferred) |

## Definition

A **concept** is an approved unit of enterprise meaning with a stable external ID and IRI. In Entropy, concepts live in a **namespace** and are one of four kinds: Entity, Shared Property, Metric, or Group.

## Concept kinds (Entropy-aligned)

| Kind | Ontology / Ossie form | Example |
| --- | --- | --- |
| `entity` | Entity / class | Customer, Order |
| `shared_property` | Reusable attribute | Email Address, SKU |
| `inline_property` | Property owned only by parent entity | Customer.internal_note |
| `metric` | Measure with unit / better-when / formula | MRR, GMV |
| `group` | Navigation container | Sales, Fulfillment |
| `value` | Enum / controlled value | OrderStatus=SHIPPED |

## Maintainable attributes

| Attribute | Required | Description |
| --- | --- | --- |
| `concept_id` / `external_id` | yes | Stable ID (Entropy external id) |
| `uri` / `iri` | yes | Resolvable IRI (Entropy semantics URL or Ossie id) |
| `kind` | yes | One of the kinds above |
| `preferred_label` | yes | Display name |
| `description` | yes | Business definition |
| `namespace` | yes | Namespace slug (`global`, `natco-de`, …) — see [Namespace Registry](../01.%20Foundation/09.%20Namespace%20Registry.md) |
| `group` | no | Subject-area group |
| `definition_ref` | no | Pointer to Modeling / Business Catalog if authored elsewhere |
| `data_type` | no | For properties |
| `classification` | no | e.g. PII |
| `unit` / `better_when` / `formula` | no | For metrics |
| `enums` / `pattern` / `examples` | no | Constraints and samples |
| `tags` / `annotations` | no | Including multi-language labels |
| `owner` / `steward` | yes | Accountable roles |
| `status` | yes | `draft` \| `review` \| `approved` \| `deprecated` |
| `version` | yes | Publication version |
| `effective_from` | yes | Active-from timestamp |
| `replaced_by` | no | Successor URI |
| `children` / `properties` | no | Inline props or shared `ref`s |

## Namespace conventions

```text
https://{entropy-host}/{org}/semantics/global/{externalId}
https://{entropy-host}/{org}/semantics/natco-{code}/{externalId}
```

Rules:

- `global` is TM Forum–seeded and globally owned; NATCOs reference it—they do not redefine it
- One `natco-{code}` namespace per NATCO; enrich from Collibra Business Catalog
- Cross-namespace edges: `sameAs` | `specializes` | `implements` | `extends` → global
- Industry imports land in `global` (preferred) or a dedicated import namespace
- IDs are opaque and stable; labels may change without changing ID

## Governance statuses

Same lifecycle: `draft` → `review` → `approved` → `deprecated`.

Only `approved` concepts may be:

- Targets of `authoritativeDefinitions` on Entropy products/contracts
- Targets of new Business / Technical / Data Product mappings
- Returned as certified by Semantic API default filters

## What to maintain vs organize

| Maintain (living) | Organize (structure only) |
| --- | --- |
| Labels, status, owner, version, properties, relationships | Folder / doc placement in MCP |
| Namespace membership and group | Duplicate glossary prose outside Entropy/Modeling |
| Audit trail of concept changes | BI-local measure names as truth |
