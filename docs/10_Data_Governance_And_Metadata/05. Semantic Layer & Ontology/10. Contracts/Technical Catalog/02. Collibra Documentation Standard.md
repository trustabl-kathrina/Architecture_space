# Collibra Documentation Standard

Every technical catalog asset type in **`10. Contracts/Technical Catalog/`** is documented the **same way**, mirroring Collibra Operating Model administration.

## Per-asset package

```text
{AssetType}/
  00. README.md           # Asset Type page (identity, parent, domain, hierarchy)
  01. Characteristics.md  # Characteristics tab (assignment table)
  contract.json           # Machine-readable type contract
  example.json            # Sample asset instance
```

## Required sections (identical order)

### `00. README.md`

| Section | Collibra analogue |
| --- | --- |
| Asset type identity | Asset Type display name, public id, parent type |
| Purpose | What the asset represents in the catalog |
| Hierarchy position | Place in Database → Schema → Table → Column |
| Recommended domain types | Where instances are stored |
| Package contents | Links to characteristics, contract, example |
| Related assets | Adjacent types in the chain |

### `01. Characteristics.md`

| Section | Collibra analogue |
| --- | --- |
| Purpose | Characteristics tab intro |
| Asset type identity | Type meta for this assignment |
| Hierarchy role | Normative relations for this type |
| Characteristics table | Same columns as Collibra Characteristics UI |
| Required / validation rules | Cardinality Min implications |
| Assignment & layout | Global vs NATCO assignment; Edit Layout note |
| Domain types | Recommended domains |
| Instance checklist | Steward / scanner acceptance criteria |
| Control Plane note | Mapping Engine `represents` guidance |
| Contracts | Links to `contract.json` + `example.json` |

## Characteristics table columns (fixed)

| Column | Meaning |
| --- | --- |
| # | Row order (assignment display order) |
| Name | Characteristic display name |
| Public ID | Characteristic / relation type public id |
| Description | Steward-facing help text |
| Kind | `Text` · `Number` · `Date` · `True/False` · `Explicit Relation` |
| Asset Type Filter | Target type for relations (`—` if attribute) |
| Min | Cardinality minimum |
| Max | Cardinality maximum (`—` = unbounded) |
| System Managed | `No` unless platform-owned |
| Read Only | `No` unless scanner-locked |
| Scope | `core` · `optional` · `regional` · `legacy` |

## Scope rules

| Scope | Use |
| --- | --- |
| `core` | Required on every enterprise / NATCO assignment |
| `optional` | Allowed on all assignments; not mandatory |
| `regional` | NATCO-only extensions (e.g. HU `_C` attributes) |
| `legacy` | Do not use for new assignments; connectors may map if present |

## Normative hierarchy (all assets)

```text
Database ──has──▶ Schema ──contains──▶ Table ──contains──▶ Column
```

Do not document Database → contains → Table as primary (legacy only).
