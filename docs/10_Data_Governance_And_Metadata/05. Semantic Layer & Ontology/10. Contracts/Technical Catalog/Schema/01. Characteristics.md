# Schema — Characteristics

Collibra **Characteristics** assignment for asset type **Schema**.  
Standard: [02. Collibra Documentation Standard](../02.%20Collibra%20Documentation%20Standard.md)

## Purpose

Define attributes and explicit relations that make up a Schema asset (Characteristics tab). Changes apply to admins until **Edit Layout** publishes the asset page.

## Asset type identity

| Field | Value |
| --- | --- |
| Asset type | Schema |
| Parent type | Technology Asset *(Operating Model dependent)* |
| Assignment level | Enterprise core + optional as marked |
| Contract | [`contract.json`](contract.json) (`ctr-tech-type-schema`) |

## Hierarchy role

```text
Database ──has──▶ ▶ Schema ──contains──▶ Table ──contains──▶ Column
```

| Name | Public ID | Target | Min | Max | Required |
| --- | --- | --- | --- | --- | --- |
| belongs to Database | `TechnologyAssetHasSchema` | Database | 1 | 1 | Yes |
| contains Table | `SchemaContainsTable` | Table | 0 | — | No (scanner / steward) |

> Collibra may show the parent filter as *Technology Asset*. Enterprise standard target filter is **Database**.

## Characteristics table

Columns match Collibra Characteristics UI. `—` in Max = unbounded. Filter `—` = attribute (not a relation).

| # | Name | Public ID | Description | Kind | Asset Type Filter | Min | Max | System Managed | Read Only | Scope |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Description | `Description` | Verbose description of what the asset means | Text | — | 1 | 1 | No | No | core |
| 2 | Description from source system | `DescriptionFromSourceSystem` | Description taken from the source / scanner | Text | — | 0 | 1 | No | No | optional |
| 3 | Location | `Location` | Location where the schema is stored or can be found | Text | — | 0 | — | No | No | optional |
| 4 | Last Sync Date | `LastSyncDate` | Date on which asset was synchronized with external system | Date | — | 0 | — | No | No | core |
| 5 | Note | `Note` | A note | Text | — | 0 | — | No | No | optional |
| 6 | belongs to Database | `TechnologyAssetHasSchema` | Links a technology asset (Database) and its associated schema (role: belongs to) | Explicit Relation | Database | 1 | 1 | No | No | core |
| 7 | contains Table | `SchemaContainsTable` | Links a schema and the tables it contains | Explicit Relation | Table | 0 | — | No | No | core |
| 8 | impacted by Issue | `IssueImpactsAsset` | Links an issue and the asset it impacts | Explicit Relation | Issue | 0 | — | No | No | optional |

## Required / validation rules

| Rule | Detail |
| --- | --- |
| R1 | Description mandatory |
| R2 | Exactly one parent Database via **belongs to Database** |
| R3 | Tables linked via **contains Table** (inverse: Table **is part of Schema**) |
| R4 | Qualified name includes database context when platform supports it |
| R5 | Last Sync Date updated on successful scanner run |

## Assignment & layout

| Topic | Guidance |
| --- | --- |
| Global Assignment | Carry all `core` characteristics |
| NATCO Assignment | May add `optional` / `regional`; must not remove `core` |
| Edit Layout | Characteristics changes are admin-only until layout is published |
| Reorder | Keep **belongs to Database** and **contains Table** adjacent |

## Domain types

Technology Asset Domain (preferred). Co-locate with parent Database where possible.

## Instance checklist

1. Display name and Description set  
2. Exactly one **belongs to Database** relation  
3. Tables registered under **contains Table**  
4. No orphan Schema without Database parent  
5. `example.json`-shaped instance validates against contract  

## Control Plane note

Structural context between Database and Table. Mapping Engine identity for meaning remains on **Table** / **Column**.
