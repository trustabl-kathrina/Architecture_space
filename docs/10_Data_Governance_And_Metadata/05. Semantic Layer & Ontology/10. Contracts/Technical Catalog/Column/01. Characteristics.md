# Column — Characteristics

Collibra **Characteristics** assignment for asset type **Column**.  
Standard: [02. Collibra Documentation Standard](../02.%20Collibra%20Documentation%20Standard.md)

## Required / validation rules

| Rule | Detail |
| --- | --- |
| R1 | Description and Description from source system mandatory |
| R2 | Column Position and Technical Data Type mandatory |
| R3 | Is Nullable and Is Primary Key mandatory |
| R4 | If Is Primary Key = true, Primary Key Name required |
| R5 | Exactly one parent Table via **is part of Table** |
| R6 | Stable catalog `source_id` / qualified name for DA-09 mappings |

## Assignment & layout

| Topic | Guidance |
| --- | --- |
| Global Assignment | Carry all `core` characteristics |
| NATCO Assignment | May add `optional` / `regional`; must not remove `core` |
| Edit Layout | Characteristics changes are admin-only until layout is published |
| Reorder | Keep technical flags (#3–#7) together; hierarchy relation (#8) near them |

## Domain types

Data Asset Domain (preferred). Co-locate with parent Table where possible.

## Instance checklist

1. Display name, Description, source description set  
2. Position, technical data type, nullability, PK flags set  
3. PK name present when Is Primary Key = true  
4. Exactly one **is part of Table**  
5. `example.json`-shaped instance validates against contract  

## Control Plane note

**Primary property mapping grain.** Column typically `represents` a property / identifier concept IRI. Classification (e.g. PII) is separate from hierarchy relations.
