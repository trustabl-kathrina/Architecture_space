# Database — Characteristics

Collibra **Characteristics** assignment for asset type **Database**.  
Standard: [02. Collibra Documentation Standard](../02.%20Collibra%20Documentation%20Standard.md)

## Purpose

Define attributes and explicit relations that make up a Database asset (Characteristics tab). Changes apply to admins until **Edit Layout** publishes the asset page.

## Asset type identity

| Field | Value |
| --- | --- |
| Asset type | Database |
| Parent type | Technology Asset |
| Assignment level | Enterprise core + optional / legacy as marked |

## Required / validation rules

| Rule | Detail |
| --- | --- |
| R1 | Description, Scope, Location mandatory (Min ≥ 1) |
| R2 | Schemas attached only via **has Schema** |
| R3 | Stable catalog `source_id` / full name for connectors |
| R4 | Last Sync Date updated on successful scanner run |

## Assignment & layout

| Topic | Guidance |
| --- | --- |
| Global Assignment | Carry all `core` characteristics |
| NATCO Assignment | May add `optional` / `regional`; must not remove `core` |
| Edit Layout | Characteristics changes are admin-only until layout is published |
| Reorder | Keep hierarchy relation (**has Schema**) near descriptive attributes |

## Domain types

Technology Asset Domain (preferred). Keep Schema children in a traversable domain tree.

## Instance checklist

1. Display name and Description set  
2. Scope and Location populated  
3. has Schema links present for known schemas  
4. No reliance on legacy **contains Table** for ingestion  
5. `example.json`-shaped instance validates against contract  

## Control Plane note

Structural context only. Prefer `represents` on **Table** / **Column**. Database may appear as parent context on mapping records.
