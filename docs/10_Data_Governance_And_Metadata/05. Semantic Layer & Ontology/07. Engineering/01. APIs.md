# Semantic APIs

## Purpose

Define the **headless API surface** of the Semantic Control Plane for Marketplace, AI, BI, and applications.

Canonical: [Architecture](../01.%20Foundation/05.%20Architecture.md).

## Scope

| In scope | Out of scope |
| --- | --- |
| Semantic, Graph, Search, MCP contracts | First-party control-plane UI |
| AuthZ, versioning, events | Vendor GraphQL product choice |

## Design principles

1. API-first — every control-plane capability is callable  
2. Default filter: `status=approved` unless explicitly overridden  
3. Stable concept URIs are primary keys  
4. Pin `ontology_version` / `ossie_version` when needed  
5. Marketplace and agents are first-class consumers  

## API families

### Semantic API

| Operation | Description |
| --- | --- |
| Lookup | Resolve concept / metric / namespace by URI or ID |
| Search | Label / synonym / facet search |
| Expand | Related concepts, dimensions, measures |
| Validate | Payload or Ossie package against schema / policies |
| Compare | Diff two concept versions or namespaces |
| Resolve | Map external ID / term → enterprise concept |

### Graph API

| Operation | Description |
| --- | --- |
| Traverse | Walk typed edges to depth N |
| Neighbors | Adjacent nodes by predicate |
| Path analysis | Shortest / constrained paths |
| Dependency / impact | Downstream of a concept or mapping change |

### Search API

Full-text, semantic, hybrid, and vector search over Registry + KG.

### MCP Server

| Capability | Notes |
| --- | --- |
| Context retrieval | Prompt / agent context from Semantics + KG |
| Semantic lookup / tools | Tool invocation for agents |
| Prompt enrichment | Inject certified URIs and definitions |

## Mapping query

`GET /mappings?source_id=&target_uri=&type=`

`type` ∈ `business` | `technical` | `data_product`

Returns: `source_id`, `target_uri`, `mapping_type`, `confidence`, `owner`, `status`, `effective_from`, `version`, `namespace`, `natco_code`, `source_system`.

## Model export

`GET /ossie/{namespace}/versions/{ver}` — download Ossie YAML/JSON package.

## AuthZ model

| Role | Read approved | Read draft | Write inventory | Manage mappings |
| --- | --- | --- | --- | --- |
| Enterprise read | policy | no | no | no |
| Domain consumer | own + shared | no | no | no |
| Domain steward | own | own | own | own |
| Architecture COE | all | all | shared | escalate |
| Platform admin | all | all | break-glass | break-glass |

Writes go through Governance Engine workflows.

## Change events

- `concept.approved` / `concept.deprecated`  
- `ossie.released`  
- `mapping.created` / `mapping.updated`  
- `federation.edge.changed`  
- `product.binding.changed`  

Consumers: Marketplace, catalog annotators, search indexers, BI sync, agents.

## Non-functional (pilot)

| Concern | Target |
| --- | --- |
| Lookup latency | Interactive (sub-second typical) |
| Availability | Control-plane SLO |
| Audit | All writes and validates logged |
