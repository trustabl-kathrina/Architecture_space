# Concept Explainers (Client Language)

Plain-language library for the pitch. Machine source: [`../examples/pitch-concepts.json`](../examples/pitch-concepts.json).

## Semantic Control Plane

**What:** System of record for what things mean enterprise-wide.  
**Why:** One certified definition of Customer, Product, Service.  
**Example:** TM Forum SID Customer in `global/`.

## Namespaces (global / natco-*)

**What:** Scopes for global vs local meaning.  
**Why:** Local labels without forking SID.  
**Example:** `natco-de/kunden` sameAs `global/customer`.

## Semantic Registry

**What:** Catalog of concepts with URIs and approval status.  
**Why:** Only approved concepts feed products and AI.  
**Example:** `…/global/customer` · approved.

## Ontology & Taxonomy

**What:** How concepts relate and classify.  
**Why:** Explicit relationships, not folklore.  
**Example:** Customer owns Account; Product realizedAs CFS.

## Knowledge / Context Graph

**What:** Connected map of assets, terms, products, policies, memory.  
**Why:** Trace “what is this column and who uses it?”  
**Example:** Customer 360 table → customer_id → PII → SID identifier → product.

## Mapping Engine

**What:** Bridges glossary, assets, and products to concepts.  
**Why:** Many sources, one meaning.  
**Example:** Collibra Kunde mapsTo Customer.

## Federation Engine

**What:** Aligns NATCO concepts to global.  
**Why:** Cross-NATCO coherence.  
**Example:** Kunden sameAs Customer.

## Governance Engine

**What:** Approval, policy, audit for meaning.  
**Why:** No silent change to certified definitions.  
**Example:** draft → review → approved before binds.

## Semantic / Graph / MCP APIs

**What:** Headless access for Marketplace, BI, and agents.  
**Why:** One backbone, many consumers.  
**Example:** Resolve Kunde → global/customer.

## Apache OSSIE

**What:** Import/export of semantic packages.  
**Why:** Partner interchange without a second SoR.  
**Example:** Export global Customer slice.

## Entropy Marketplace

**What:** UI and SoR for data products.  
**Why:** Discovery + lifecycle; meaning comes from the control plane.  
**Example:** global-customer-360 implements Customer + Customer Account.
