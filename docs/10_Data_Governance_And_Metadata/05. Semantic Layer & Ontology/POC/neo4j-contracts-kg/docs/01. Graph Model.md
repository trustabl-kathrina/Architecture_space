# Graph Model

Maps [`10. Contracts`](../../../10.%20Contracts/) asset types and cross-pack relations into Neo4j labels and relationships.

## Pack → labels

| Pack | Node labels |
| --- | --- |
| Semantic Control Plane | `Namespace`, `Concept`, `MappingRecord`, `FederationEdge` |
| Business Catalog | `BusinessTerm`, `DataDomain`, `DataModel`, `DataEntity`, `DataAttribute` |
| Technical Catalog | `System`, `Database`, `Schema`, `Table`, `Column` |
| Data Products | `DataProduct`, `OutputPort`, `InputPort`, `DataContract`, `ContractField` |

Common properties: `id` (unique), `name` / `preferredLabel`, `status`, `owner`, `pack`.

## Structural relationships (within pack)

```
Namespace -[:CONTAINS_CONCEPT]-> Concept
Concept -[:FEDERATES]-> Concept
Concept -[:FROM_CONCEPT]-> FederationEdge -[:TO_CONCEPT]-> Concept

DataDomain -[:OWNS_MODEL]-> DataModel -[:CONTAINS_ENTITY]-> DataEntity -[:HAS_ATTRIBUTE]-> DataAttribute
DataDomain -[:CLASSIFIES]-> DataEntity
BusinessTerm -[:RELATES_TO]-> DataEntity

System -[:HAS_DATABASE]-> Database -[:HAS_SCHEMA]-> Schema
  -[:CONTAINS_TABLE]-> Table -[:CONTAINS_COLUMN]-> Column

DataProduct -[:EXPOSES]-> OutputPort -[:GOVERNED_BY]-> DataContract -[:CONTAINS_FIELD]-> ContractField
DataProduct -[:CONSUMES]-> InputPort
```

## Meaning bridges (→ Concept)

| Rel | Source packs | Contracts DA |
| --- | --- | --- |
| `MAPS_TO` | Business → Concept | DA-08 |
| `REPRESENTS` | Technical → Concept | DA-09 |
| `IMPLEMENTS` | Product → Concept | DA-10 |

Each bridge also has a `MappingRecord` node with `SOURCE` / `TARGET` edges for audit.

## Structural bridges (cross-pack)

| Rel | Meaning |
| --- | --- |
| `IMPLEMENTED_IN` / `IMPLEMENTS_ENTITY` | Entity ↔ Table |
| `IMPLEMENTED_BY` / `IMPLEMENTS_ATTRIBUTE` | Attribute ↔ Column |
| `BACKED_BY` | OutputPort → Table |
| `READS_FROM` | InputPort → Table |
| `MAPS_TO_COLUMN` | ContractField → Column |
| `BELONGS_TO_DOMAIN` | DataProduct → DataDomain |

## Seed scenario

Customer 360 from [`end-to-end-customer-flow.json`](../../../10.%20Contracts/examples/end-to-end-customer-flow.json):

- Concepts: `global/customer`, `global/customer-identifier`, `natco-de/kunde` (federated)
- CRM table `crm.public.customer` + curated `dp.curated.customer_360`
- Product `Customer 360` with ports, contract, and field `customer_id`

## Design notes

- **Concept is the meaning hub** — prefer querying outward from `Concept` for impact analysis.
- Each NATCO has a full local stack (namespace, concepts, glossary, CRM table/column) linked to global via `ALIGNS_TO` / `FEDERATES` / `MAPS_TO` / `REPRESENTS`.
- Contracts JSON + [`POC/examples/multi-natco-customer-assets.json`](../../examples/multi-natco-customer-assets.json) remain documentation SoR; this graph is a **demo materialization**.
- Extend by adding MERGE seed files per new example; keep constraint file updated for new labels.
