# 2. Architecture of Mage

## Control plane vs execution plane

| Plane | Responsibility |
| --- | --- |
| **Control plane** | Mage server (UI, API, scheduler, project repo) |
| **Execution plane** | Block executors (Python, SQL, PySpark, dbt, etc.) |

## Core components

| Component | Function |
| --- | --- |
| **Project** | Git-backed folder of pipelines, blocks, metadata |
| **Pipeline** | DAG of blocks with upstream/downstream dependencies |
| **Block** | Notebook-style unit (loader, transformer, exporter) |
| **Scheduler** | Cron, API, or event triggers for pipeline runs |
| **Metadata DB** | Postgres/SQLite for run history and secrets refs |

Mage targets teams that want **notebook velocity with production scheduling** — less ceremony than full Airflow platform setup for mid-size pipelines.

## Design principle

**Blocks + pipelines** — author interactively in UI or IDE; promote the same code to scheduled production runs.
