# 7. How to Configure Composer for Production

## Configuration matrix

| Goal | Environment settings | DAG settings | Monitoring |
| --- | --- | --- | --- |
| **T0 SLA (06:00 finish)** | Medium+ size; min workers 2; max 20 | `max_active_runs=1`; pools; timeouts | SLA sensor; PagerDuty |
| **Cost-efficient dev** | Small; min workers 1; max 3 | `catchup=False`; no schedules in dev | Budget alerts |
| **High parallelism** | Large size; high max workers | Pools per warehouse; priority weights | Queue depth alert |
| **Private / regulated** | Private IP; VPC-SC; CMEK | Secret Manager connections | Audit log sinks |
| **Fast DAG iteration** | Staging mirrors prod version | CI import test | Parse error alert |

## Recipe 1 — T0 finance close DAG

**Target:** Complete ledger pipeline by 06:00 UTC with audit trail.

```yaml
environment:
  size: ENVIRONMENT_SIZE_MEDIUM
  scheduler_count: 2
  worker_min: 3
  worker_max: 16
  private_ip: true
dag:
  schedule: "0 1 * * *"
  max_active_runs: 1
  catchup: false
  default_args:
    retries: 3
    retry_delay: 5m
    execution_timeout: 2h
  pools:
    bigquery_finance: 8 slots
sla:
  deadline_sensor: "05:45 UTC"
  on_failure: pagerduty_t0
```

- Dedicated **pool** for finance BigQuery jobs.
- **SLA sensor** fails DAG run if not complete by 05:45 — triggers escalation before business deadline.

## Recipe 2 — High-volume hourly loads

**Target:** 24 hourly DAG runs with 200 parallel tasks peak.

```yaml
environment:
  size: ENVIRONMENT_SIZE_LARGE
  worker_min: 4
  worker_max: 30
dag:
  schedule: "@hourly"
  concurrency: 32
  max_active_tasks: 64
tasks:
  use_deferrable: true  # for sensors
  offload_spark: DataprocSubmitJobOperator
```

- Enable **deferrable** sensors to avoid worker blocking.
- Submit Spark to **Dataproc Serverless** — worker only polls job status.

## Recipe 3 — Private enterprise environment

```yaml
network:

  cloud_sql_ipv4_cidr: 10.0.10.0/24

  worker_sa: composer-prod@PROJECT.iam.gserviceaccount.com
  roles: [bigquery.jobUser, storage.objectViewer, dataproc.editor]
```

## Recipe 4 — Event-driven supplemental runs

```
Eventarc (GCS) → Pub/Sub → Cloud Function → Airflow REST API
POST /api/v1/dags/partner_load/dagRuns
Body: {"conf": {"uri": "gs://landing/partner/file.parquet"}}
```

- Keep **scheduled** and **event** DAGs separate to simplify SLA reporting.
- Use idempotent partition keys in `conf`.

## Recipe 5 — Backfill after logic fix

1. Pause DAG schedule (`is_paused`) if needed.
2. Deploy fixed DAG via CI.
3. Trigger backfill: `airflow dags backfill -s 2026-01-01 -e 2026-01-31 orders_daily`
4. Cap parallelism with `--reset-dagruns` and pool limits.
5. Notify downstream consumers.

## Recipe 6 — Multi-environment promotion

| Env | Workers | Schedule | Connections |
| --- | --- | --- | --- |
| dev | 1–3 | Manual / frequent | dev BQ project |
| staging | 2–6 | Mirror prod offset | staging BQ |
| prod | 3–16 | Business cron | prod BQ |

Same Git branch artifact promoted; only Airflow **Variables** differ.

## Monitoring thresholds

| Metric | Warning | Critical |
| --- | --- | --- |
| Task queue depth | > 100 for 15 min | > 500 |
| Scheduler heartbeat gap | > 2 min | > 5 min |
| DAG run duration vs SLA | > p95 baseline | Miss deadline sensor |
| Worker utilization | max workers 80% for 1 hr | Sustained 100% |
| Import errors | > 0 | Any in prod after deploy |
