# 6. AWS Step Functions Costing

> **Source of truth:** [AWS Step Functions pricing](https://aws.amazon.com/step-functions/pricing/) — verify before budgeting.

## Cost components

Step Functions charges for **orchestration only** — Lambda, Glue, and other task targets billed separately.

| Workflow type | Billing model |
| --- | --- |
| **Standard** | Per **state transition** (each completed step, including retries) |
| **Express** | Per **execution request** + **duration** (GB-second memory) |

## Standard workflow pricing

| Category | Rate (typical us-east-1) |
| --- | --- |
| State transitions | **$0.025** per 1,000 transitions |
| Free tier | 4,000 transitions/month |

```
monthly_standard_cost = (total_transitions - 4000) / 1000 * $0.025
```

Each **Retry** attempt counts as additional transitions.

## Express workflow pricing

| Category | Rate (typical) |
| --- | --- |
| Execution requests | **$1.00** per 1 million requests |
| Duration | **$0.00001667** per GB-second (64 MB–256 MB chunks) |

Express is often **10–40× cheaper** than Standard for short workflows (&lt; 10 states, &lt; 30 s) at high volume.

## Scenario cost models

### Scenario A — Dev / test (Standard)

| Assumption | Value |
| --- | --- |
| Executions | 500/month × 6 transitions |
| Total transitions | 3,000 |
| **Est. cost** | **$0** (within free tier) |

### Scenario B — S3 trigger pipeline (Standard)

| Assumption | Value |
| --- | --- |
| Files | 100,000/month |
| Transitions per execution | 8 |
| Total transitions | 800K → **~$19/month** |
| **Plus Glue/Lambda** | Dominates if jobs are large |

### Scenario C — High-frequency health check (Express)

| Assumption | Value |
| --- | --- |
| Executions | 1M/month |
| Avg duration | 2 s at 64 MB |
| **Express total** | **~$3–5/month** orchestration |
| Same on Standard (5 states) | **~$125/month** |

### Scenario D — Step Functions vs MWAA (sparse)

| | Step Functions | MWAA (mw1.small) |
| --- | --- | --- |
| 1,000 runs/month × 8 transitions | ~$0.20 | **~$353+** environment baseline |
| **Winner** | Sparse / event-driven | Dense daily batch |

## Standard vs Express crossover (rule of thumb)

| Profile | Prefer |
| --- | --- |
| &lt; 10 states, &gt; 100K runs/month, &lt; 5 min | **Express** |
| Human callback, &gt; 5 min, audit history | **Standard** |
| Long Glue `.sync` jobs | **Standard** (Express timeout) |

## Cost optimization

1. **Choose Express** when duration and semantics allow.
2. **Reduce states** — merge Pass/Choice chains where readable.
3. **Cap retries** — each retry bills transitions.
4. **Nested workflows** — avoid duplicate transition overhead where possible.
5. **Distributed Map** — compare Map vs single Glue job for bulk.
6. **Monitor** `TransitionCount` per execution in metrics.
