# 3. How to Use AWS Step Functions

## Setup prerequisites

1. IAM **execution role** with policies for target services (Lambda, Glue, S3).
2. Choose **workflow type** — Standard vs Express.
3. Region alignment with data sources (S3, Glue jobs).
4. Naming: `sf-{domain}-{purpose}-{env}`.

## Define state machine (ASL — S3 event → Glue)

**`state-machine.asl.json`:**

```json
{
  "Comment": "S3 landing to Glue ETL",
  "StartAt": "StartGlueJob",
  "States": {
    "StartGlueJob": {
      "Type": "Task",
      "Resource": "arn:aws:states:::glue:startJobRun.sync",
      "Parameters": {
        "JobName": "orders-etl-prod",
        "Arguments": {
          "--input.$": "$.detail.object.key"
        }
      },
      "Retry": [{
        "ErrorEquals": ["Glue.ConcurrentRunsExceededException"],
        "IntervalSeconds": 60,
        "MaxAttempts": 5,
        "BackoffRate": 2
      }],
      "End": true
    }
  }
}
```

## Deploy (AWS CLI)

```bash
aws stepfunctions create-state-machine \
  --name sf-orders-landing-prod \
  --definition file://state-machine.asl.json \
  --role-arn arn:aws:iam::ACCOUNT:role/sf-orders-execution-prod \
  --type STANDARD
```

Update definition:

```bash
aws stepfunctions update-state-machine \
  --state-machine-arn arn:aws:states:us-east-1:ACCOUNT:stateMachine:sf-orders-landing-prod \
  --definition file://state-machine.asl.json
```

## Start execution

```bash
aws stepfunctions start-execution \
  --state-machine-arn arn:aws:states:us-east-1:ACCOUNT:stateMachine:sf-orders-landing-prod \
  --input '{"detail":{"object":{"key":"landing/orders/2026-06-20/file.parquet"}}}'
```

## EventBridge trigger (S3 via EventBridge)

```json
{
  "source": ["aws.s3"],
  "detail-type": ["Object Created"],
  "detail": {
    "bucket": {"name": ["orders-landing-prod"]},
    "object": {"key": [{"prefix": "landing/"}]}
  }
}
```

Target: Step Functions state machine ARN with **input transformer** mapping event to execution input.

## Callback pattern (human approval)

```json
"WaitForApproval": {
  "Type": "Task",
  "Resource": "arn:aws:states:::lambda:invoke.waitForTaskToken",
  "Parameters": {
    "FunctionName": "send-approval-request",
    "Payload": {
      "taskToken.$": "$$.Task.Token",
      "executionInput.$": "$"
    }
  },
  "Next": "ProcessAfterApproval"
}
```

External system calls `SendTaskSuccess` / `SendTaskFailure` with the task token.

## Map state (parallel regions)

```json
"ProcessRegions": {
  "Type": "Map",
  "ItemsPath": "$.regions",
  "MaxConcurrency": 5,
  "Iterator": {
    "StartAt": "RunRegionalGlue",
    "States": {
      "RunRegionalGlue": {
        "Type": "Task",
        "Resource": "arn:aws:states:::glue:startJobRun.sync",
        "Parameters": {
          "JobName": "regional-etl",
          "Arguments": {"--region.$": "$.name"}
        },
        "End": true
      }
    }
  },
  "End": true
}
```

## IAM patterns

| Role | Trust / permissions |
| --- | --- |
| **State machine execution role** | Trust `states.amazonaws.com`; Glue/Lambda/S3 scoped policies |
| **EventBridge invoke role** | `states:StartExecution` on target ARN |
| **Human callback** | `states:SendTaskSuccess` limited to approval Lambda role |

## Terraform

```hcl
resource "aws_sfn_state_machine" "orders" {
  name     = "sf-orders-landing-prod"
  role_arn = aws_iam_role.sf_exec.arn
  type     = "STANDARD"
  definition = file("state-machine.asl.json")
}
```

## Observability

- **Console:** Visual execution graph with per-state I/O.
- **CloudWatch Logs** — enable logging on state machine (Express requires this for history).
- **X-Ray** — trace integration latency.
- **Metrics:** `ExecutionsStarted`, `ExecutionsFailed`, `ExecutionTime`.

## Operational checklist

- [ ] Execution role least privilege per state machine
- [ ] Retry policies on external Task states
- [ ] Idempotent Glue/Lambda downstream
- [ ] Payload size &lt; 256 KB or use S3 reference
- [ ] Standard vs Express chosen deliberately
- [ ] ASL in version control (not console-only)
