# 7. How to Configure Glue Workflows for Production

## Configuration matrix

| Goal | Workflow settings | Job settings | Monitoring |
| --- | --- | --- | --- |
| **T0 SLA** | Single schedule trigger; MaxConcurrentRuns=1 | Standard class; adequate workers | CloudWatch alarm on run FAILED |
| **Cost-efficient batch** | Off-peak cron | **FLEX** execution class | Cost anomaly detection |
| **Incremental freshness** | Hourly schedule | Job bookmark ON | Data age metric |
| **Event-driven landing** | EventBridge trigger | Idempotent writes | DLQ via failed job notify |
| **Regulated data** | LF permissions | KMS encryption; VPC conn | Audit S3 + LF logs |

## Recipe 1 — T0 nightly medallion

```yaml
workflow:
  name: wf-finance-medallion-prod
  max_concurrent_runs: 1
trigger_start:
  type: SCHEDULED
  schedule: "cron(0 1 * * ? *)"
jobs:
  bronze:
    execution_class: STANDARD
    worker_type: G.2X
    number_of_workers: 10
  silver:
    execution_class: STANDARD
    worker_type: G.2X
    number_of_workers: 12
```

Use **Standard** execution class for predictable start time on finance close.

## Recipe 2 — Flex off-peak enrichment

```yaml
jobs:
  enrichment:
    execution_class: FLEX
    worker_type: G.1X
    number_of_workers: 6
    schedule: "cron(0 3 * * ? *)"  # after T0 window
```

Accept variable startup latency for ~35% DPU savings.

## Recipe 3 — Incremental with bookmarks

- Enable bookmark on source node in job definition (`--job-bookmark-option job-bookmark-enable`).
- Downstream conditional trigger on `SUCCEEDED` only.
- Document **reset procedure** in runbook (requires admin IAM).

## Recipe 4 — Workflow run properties for partitions

```bash
aws glue start-workflow-run \
  --name wf-orders-medallion-prod \
  --run-properties '{"partition_date":"2026-06-20","force_reload":"false"}'
```

Bronze job reads properties; silver inherits via `putWorkflowRunProperties`.

## Recipe 5 — Hybrid platform boundary

| Layer | Tool |
| --- | --- |
| In-Glue medallion | Glue Workflows |
| Redshift load + dbt | MWAA DAG triggered after workflow SUCCESS (EventBridge or Lambda poll) |
| S3 virus scan / notify | Step Functions before `StartWorkflowRun` |

## Recipe 6 — Concurrency and queuing

- Set workflow **`MaxConcurrentRuns`** to prevent overlapping schedules during slow runs.
- Enable **job queuing** at account level when hitting concurrent run limits (15-min queue window).
- Stagger workflows that share account DPU quota.

## Monitoring thresholds

| Signal | Warning | Critical |
| --- | --- | --- |
| Workflow run FAILED | Any T0 failure | 2 consecutive nights |
| Job duration p99 | &gt; 2× baseline | &gt; SLA window |
| Crawler schema changes | New columns detected | Breaking type change |
| DPU hours daily | &gt; 120% of 7-day avg | &gt; 200% of avg |
| Bookmark lag | &gt; 2× expected interval | Stalled &gt; 24 hr |
