# 6. Azure Logic Apps Costing

> **Source of truth:** [Azure Logic Apps pricing](https://azure.microsoft.com/pricing/details/logic-apps/) — verify before budgeting.

## Cost components

### Consumption plan

| Component | Typical rate |
| --- | --- |
| **Built-in actions** | First 4,000 actions/month free; then ~$0.000025/action |
| **Standard connectors** | Per action (varies by connector) |
| **Enterprise connectors** | Premium tier — significantly higher |
| **Data retention** | ~$0.12/GB/month for run history storage |

Billing is **per trigger and action execution** — no cost when idle.

### Standard plan

| Component | Typical rate |
| --- | --- |
| **App Service plan** | Dedicated vCPU + memory (e.g., ~$140/vCPU/month + memory) |
| **Built-in actions** | Many unlimited on Standard |
| **Managed connectors** | Same connector tiers as Consumption |

Standard has **baseline cost** even at zero runs — like MWAA but typically lower for single app.

## Scenario cost models

### Scenario A — Dev / alerts (Consumption)

| Assumption | Value |
| --- | --- |
| Runs | 500/month × 3 actions |
| Total actions | 1,500 |
| **Est. cost** | **$0** (within free tier) |

### Scenario B — ADF failure alerts (Consumption)

| Assumption | Value |
| --- | --- |
| Failures | 50/month × 4 actions |
| Actions | 200 |
| **Est. cost** | **~$0** |

### Scenario C — High-volume webhook (Consumption)

| Assumption | Value |
| --- | --- |
| Executions | 100K/month × 5 actions |
| Actions | 500K → (500K - 4K) × $0.000025 ≈ **~$12/month** |

### Scenario D — Enterprise connector workflow

| Assumption | Value |
| --- | --- |
| SAP actions | 10K/month premium tier |
| **Est. cost** | **$100s+** — validate connector pricing page |

### Scenario E — Consumption vs Standard crossover

| Profile | Consumption | Standard (WS1) |
| --- | --- | --- |
| 10K runs/mo, 5 actions | ~$1–2 | ~$150+ plan baseline |
| 1M runs/mo, 8 actions | ~$200 | Standard may win + VNet |

Use **Consumption** for sparse ops glue; **Standard** for VNet, steady high volume, or long-running stateful workflows.

### Scenario F — Logic Apps vs ADF for orchestration only

| | Logic Apps | ADF |
| --- | --- | --- |
| 3-step alert chain | ~$0.01 | Activity run + IR minutes |
| 50-step ELT | Expensive per action | **ADF** designed for this |

## Cost optimization

1. **Built-in HTTP** instead of premium connectors where possible.
2. **Managed identity** — avoid paid auth maintenance overhead.
3. **Consolidate actions** — merge Compose steps thoughtfully.
4. **Retention policy** — trim run history storage.
5. **Budget alerts** on Logic Apps resource group.
6. **Don't ETL in Logic Apps** — offload to ADF.
