# 7. How to Configure Logic Apps for Production

## Configuration matrix

| Goal | Plan | Workflow design | Monitoring |
| --- | --- | --- | --- |
| **Cost-efficient alerts** | Consumption | Built-in + MI | Budget alert |
| **VNet private APIs** | Standard | VNet integration | App Insights |
| **Reliable ADF invoke** | Either | Retry + timeout on HTTP | Failed runs alert |
| **Human approval** | Standard preferred | Approval action | Escalation timer |
| **Audit** | Either | Diagnostic → Log Analytics | Retention policy |

## Recipe 1 — ADF failure alert (Consumption)

- Event Grid system topic on Data Factory resource.
- Filter: `PipeLineRun.Failed` only (reduce noise).
- Teams adaptive card with pipeline name, run ID, error message link.
- Retry policy on Teams action (429 throttling).

## Recipe 2 — Standard plan in VNet

- Deploy Logic App (Standard) into **App Service plan** with VNet integration.
- Private DNS for internal API endpoints.
- Use **built-in HTTP** for internal services — avoid public internet.

## Recipe 3 — Idempotent webhook ingress

```
HTTP Request → Parse body → Lookup Storage table by eventId → Condition exists → Terminate : else → ADF createRun
```

Handles at-least-once Event Grid delivery.

## Recipe 4 — Managed identity for ADF REST

Assign Logic App MI role: `Microsoft.DataFactory/factories/pipelines/createRun/action` on factory scope.

## Recipe 5 — Secret management

- Key Vault references in connection strings.
- No secrets in workflow run history — use secure inputs where supported.

## Monitoring thresholds

| Signal | Warning | Critical |
| --- | --- | --- |
| Runs failed rate | &gt; 1% | &gt; 5% |
| Action latency p99 | &gt; 10 s | &gt; 30 s |
| Connector 429 rate | &gt; 0 sustained | Alert storm |
| Standard plan CPU | &gt; 70% | &gt; 90% sustained |
