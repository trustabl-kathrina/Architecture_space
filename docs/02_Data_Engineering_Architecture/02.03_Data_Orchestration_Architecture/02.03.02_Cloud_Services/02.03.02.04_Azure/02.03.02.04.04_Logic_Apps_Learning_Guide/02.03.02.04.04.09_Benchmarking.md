# 9. Azure Logic Apps Benchmarking

Reference profiles for **action budgeting and plan selection** before production.

## Methodology

1. Deploy workflow to **staging** (Consumption or Standard).
2. Synthetic load via Event Grid replay or HTTP generator.
3. Measure: end-to-end latency, action count, failure rate, connector throttling.
4. Compare Consumption vs Standard using [Costing](02.03.02.04.04.06_Costing.md).

## Reference scenarios

| ID | Profile | Actions/run | Volume | Measure |
| ---: | --- | ---: | ---: | --- |
| L1 | Teams alert only | 2 | 1K/month | Baseline latency |
| L2 | ADF invoke + Teams | 4 | 500/month | ADF REST latency |
| L3 | Event Grid burst | 3 | 5K in 10 min | Throttling / 429 |
| L4 | HTTP webhook ingress | 5 | 50K/month | Consumption cost |
| L5 | Approval workflow | 6 + wait | 200/month | Duration limits |
| L6 | ForEach 20 items | 20+ | 100/month | Loop cap behavior |
| L7 | Standard VNet HTTP | 3 | 100K/month | p99 latency vs Consumption |
| L8 | Retry stress (fail 2×) | 4 × 3 attempts | 500/month | Action billing impact |

## Expected outcomes (indicative)

| Profile | p50 latency | Notes |
| --- | --- | --- |
| L1 | &lt; 3 s | Connector bound |
| L3 burst | Some 429 without retry | Configure retry policy |
| L7 Standard | Lower p99 under load | Plan baseline cost applies |
| L5 Consumption | May hit duration cap | Prefer Standard for long approvals |

## Anti-patterns in benchmarks

- **L6 large loops** — use ADF ForEach for bulk data processing.
- **Uncapped recurrence** — inflates Consumption action count.
