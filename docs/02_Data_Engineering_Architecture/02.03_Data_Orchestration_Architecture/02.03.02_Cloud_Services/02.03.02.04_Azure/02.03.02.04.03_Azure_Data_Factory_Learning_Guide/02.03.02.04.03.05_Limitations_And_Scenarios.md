# 5. Limitations and Mitigation Scenarios

## Platform limits (summary)

Source: [ADF limits](https://learn.microsoft.com/en-us/azure/data-factory/limits) — verify current values.

| Limit | Typical impact | Mitigation |
| --- | --- | --- |
| **Concurrent pipeline runs** | Queueing / throttling | Split factories; optimize duration |
| **Activities per pipeline** | Design complexity | Nested Execute Pipeline |
| **SHIR single-node** | HA risk | Multi-node SHIR cluster |
| **Mapping data flow min vCores** | Cost floor (~8 vCore) | Use Synapse/Databricks for small transforms |
| **No portable DAG code** | Vendor lock-in | Document; use Airflow for portable tier |
| **Debug session cost** | Accidental spend | Auto-shutdown policies |
| **Wait activity billing** | Long waits costly | Logic Apps or Durable Functions for wait |

## Limitation → mitigation

| Limitation | Scenario | Mitigation |
| --- | --- | --- |
| Complex Python logic | Custom ML prep | Databricks/Synapse notebook activity |
| Cross-cloud orchestration | AWS + Azure | Separate control planes + metadata bus |
| Fine-grained backfill UI | Airflow-style | Tumbling window + parameter loops |
| Real-time sub-second | Streaming | Event Hubs + Stream Analytics, not ADF |
| Git merge conflicts | Large team | Branch policies; modular pipelines |

## When not to use ADF

| Situation | Better fit |
| --- | --- |
| Portable Airflow investment | **AKS Airflow** / **MWAA** |
| Simple alert on failure | **Logic Apps** alone |
| High-frequency micro orchestration | **Logic Apps Consumption** |
| AWS-native lake | **Glue/MWAA** |

## Risk scenarios

### SHIR node failure

**Symptom:** Hybrid copies fail.  
**Mitigation:** 2+ SHIR nodes; monitoring agent; auto-failover docs.

### DIU under-provisioning

**Symptom:** Copy SLA miss.  
**Mitigation:** Benchmark DIU; parallel copy; partition files.

### UI-only prod changes

**Symptom:** Drift from Git.  
**Mitigation:** Disable direct publish; ARM pipeline required.
