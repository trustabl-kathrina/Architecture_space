# Enterprise DataOps Playbook

Operational playbook for running orchestrated data pipelines at enterprise scale. Use alongside [DataOps Framework](02.03.01.05.01_DataOps_Framework.md) and [Orchestration Governance](../02.03.01.04_Governance/02.03.01.04.01_Orchestration_Governance.md).

## Phase 0 — Foundation (weeks 1–4)

| Step | Action | Owner | Deliverable |
| --- | --- | --- | --- |
| 0.1 | Inventory schedulers (cron, legacy ETL, cloud jobs) | Platform | Scheduler census spreadsheet |
| 0.2 | Select primary orchestrator ([Strategy doc](../02.03.01.02_Strategy/02.03.01.02.01_Orchestration_Strategy.md)) | Architecture | ADR signed |
| 0.3 | Provision dev/staging/prod control planes | Platform | HA metadata DB, RBAC, SSO |
| 0.4 | Define SLA tiers T0–T3 | Governance + domains | Tier tagging standard |
| 0.5 | Create DAG repo template (cookiecutter) | Platform | Golden path repo |

## Phase 1 — Migration (weeks 5–16)

| Step | Action | Notes |
| --- | --- | --- |
| 1.1 | Migrate **T0** pipelines first — highest business risk if delayed | One domain pilot |
| 1.2 | Replace time-only dependencies with sensors or datasets | Document data contracts |
| 1.3 | Implement standard operators (warehouse, Spark, dbt) | Operator allowlist |
| 1.4 | Parallel run old cron + new DAG until 2 successful weeks | Cutover checklist |
| 1.5 | Decommission legacy scheduler for migrated jobs | Archive run history |

**Migration cutover checklist:**

- [ ] Idempotent partition logic verified
- [ ] Retries and alerts configured
- [ ] Staging run passed
- [ ] Consumers notified of new freshness path
- [ ] Rollback plan documented (re-enable cron)

## Phase 2 — DataOps automation (weeks 12–24)

| Step | Action | Tooling |
| --- | --- | --- |
| 2.1 | CI on every PR: parse, lint, test, secret scan | GitHub Actions / GitLab CI |
| 2.2 | CD to staging on merge to `main`; prod on tagged release | Git-sync / object storage deploy |
| 2.3 | Embed data quality tasks in T0/T1 DAGs | dbt tests, GE, SQL checks |
| 2.4 | OpenLineage on task start/complete | Marquez / DataHub |
| 2.5 | SLA dashboard and paging rules | Datadog / Grafana + PagerDuty |

## Phase 3 — Scale and federate (ongoing)

| Step | Action |
| --- | --- |
| 3.1 | Enable domain repos with shared CI library (`airflow-platform-lib`) |
| 3.2 | Introduce dataset/asset triggers — reduce external sensors 50%+ |
| 3.3 | Chargeback reports by `domain` tag |
| 3.4 | Quarterly DR drill — restore metadata DB, validate scheduler failover |
| 3.5 | [Active metadata](../02.03.01.06_Active_Metadata/02.03.01.06.01_Active_Metadata.md) pilot — auto-ticket on SLA breach |

## Daily operations runbook

| Situation | Steps |
| --- | --- |
| **Task failed (T0)** | Ack page → check logs → if transient, clear task → if data bug, pause DAG → notify consumers |
| **SLA at risk** | Check running task duration → scale pool / priority → escalate if < 30 min to deadline |
| **Scheduler down** | Failover to standby / restart scheduler → verify heartbeat → assess missed runs → manual trigger T0 |
| **Bad deploy** | Pause affected DAGs → revert Git deploy → backfill if corrupt data written |
| **Upstream late** | Coordinate with source team → extend consumer comms → avoid unsafe "force success" |

## Release calendar coordination

- **Freeze windows** — No prod DAG deploys during month-end close (T0 finance).
- **Blackout days** — Peak retail/events: change advisory only.
- **Maintenance** — Orchestrator upgrades in low-traffic window with rollback image ready.

## Roles and on-call

| Role | Responsibility |
| --- | --- |
| **Platform on-call** | Scheduler, workers, metadata DB, deploy pipeline |
| **Domain on-call** | DAG logic, data quality failures, consumer comms |
| **Escalation** | T0 miss > 30 min → data platform lead + business owner |

Runbooks linked from every T0 DAG (`runbook_url` tag).

## KPIs (review monthly)

| KPI | Target direction |
| --- | --- |
| T0 on-time completion rate | ↑ > 99% |
| Mean time to recover (T0) | ↓ |
| Prod deploys via CI (vs UI) | ↑ 100% |
| DAGs with required metadata | ↑ 100% |
| Failed runs due to deploy regression | ↓ |
| Sensor count per domain | ↓ (shift to datasets) |

## Common pitfalls

1. **Big-bang migration** — Migrate in waves by tier and domain.
2. **UI-only prod fixes** — Always backport to Git within 24h.
3. **Ignoring idempotency** — Retries duplicate rows; fix before T0 cutover.
4. **Unbounded backfill** — Cap concurrency; notify consumers.
5. **Skipping staging** — Staging catches 80% of deploy issues.
