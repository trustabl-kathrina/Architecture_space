# DataOps Maturity Model (Orchestration Focus)

Assess how effectively an organization delivers and operates orchestrated data pipelines. Each level builds on the previous; skipping levels creates fragile automation.

## Maturity levels

| Level | Name | Orchestration characteristics | Typical pain |
| --- | --- | --- | --- |
| **1** | Ad hoc | Cron scripts, manual reruns, email alerts | Unknown status; hero culture |
| **2** | Repeatable | Central orchestrator; some Git DAGs | UI hotfixes; inconsistent testing |
| **3** | Defined | CI/CD, RBAC, SLA tiers, staging env | Slow releases; partial lineage |
| **4** | Managed | Metrics-driven SLAs, chargeback, dataset triggers | Optimization needed at scale |
| **5** | Optimizing | Active metadata, self-service golden paths, continuous improvement | Innovation on top of stable base |

## Assessment dimensions

Score each dimension 1–5 (see criteria below).

| Dimension | L1 | L3 | L5 |
| --- | --- | --- | --- |
| **Source control** | Scripts on servers | All prod DAGs in Git | Immutable deploy artifacts + SHA in runs |
| **CI/CD** | Manual copy | Automated deploy to staging/prod | Canary / blue-green DAG deploy |
| **Testing** | Production is test | CI parse + staging integration | Unit + contract + prod anomaly checks |
| **Orchestration ops** | Single server | HA scheduler + metadata DB backup | Auto-scaling workers; DR drills |
| **Observability** | Log grep | Central dashboards + paging | SLA error budgets; lineage-driven impact |
| **Governance** | Tribal knowledge | RBAC + required tags | Policy-as-code; audit exports |
| **Metadata integration** | None | Catalog links manual | Dataset triggers; active metadata actions |
| **Self-service** | Ticket to platform | Templates for domains | IDP with guardrailed autonomy |

## Level detail — orchestration

### Level 1 — Ad hoc

- Cron on individual VMs; SSH to rerun.
- No central view of dependencies.
- Failures discovered by downstream users.

**Exit criteria:** Central orchestrator deployed; critical pipelines migrated.

### Level 2 — Repeatable

- Airflow/Composer/MWAA in use.
- Some DAGs in Git; others edited in UI.
- Basic retry and email on failure.

**Exit criteria:** Prod changes only via Git; CI DAG parse on all repos.

### Level 3 — Defined

- CI/CD to dev/staging/prod orchestrators.
- SLA tiers (T0–T3) tagged on DAGs.
- Staging integration runs required for T0/T1.
- RBAC and secrets in vault.

**Exit criteria:** 90%+ prod deploys via pipeline; SLA dashboard live.

### Level 4 — Managed

- Dataset-aware or asset-based triggers reduce sensor sprawl.
- Domain chargeback for compute and orchestrator workers.
- Error budgets and incident postmortems for T0 misses.
- OpenLineage or equivalent on all prod tasks.

**Exit criteria:** Measurable SLA improvement YoY; federated domains on shared standards.

### Level 5 — Optimizing

- [Active metadata](../02.03.01.06_Active_Metadata/02.03.01.06.01_Active_Metadata.md) automates quarantine, reruns, or scaling.
- Self-service golden paths with automated policy checks.
- Experimentation with cost-aware scheduling (FinOps loops).

## Scoring and roadmap

1. **Assess** — Workshop with platform + 2–3 domain teams; score each dimension.
2. **Baseline** — Average score maps to overall level (floor of dimension minimum for T0 domains).
3. **Prioritize** — Fix T0 domains at lowest dimension first (often testing or CI).
4. **Quarterly re-assess** — Track dimension deltas.

| Overall score | Level |
| --- | --- |
| 1.0 – 1.9 | 1 |
| 2.0 – 2.9 | 2 |
| 3.0 – 3.9 | 3 |
| 4.0 – 4.4 | 4 |
| 4.5 – 5.0 | 5 |

## Quick wins by current level

| From → To | Highest ROI actions |
| --- | --- |
| 1 → 2 | Migrate top 10 cron jobs to orchestrator; standard alerting |
| 2 → 3 | Enforce Git-only prod; add CI `DagBag` test; staging environment |
| 3 → 4 | SLA dashboard; dataset triggers; OpenLineage |
| 4 → 5 | Active metadata pilot on one domain; IDP templates |
