# Event Modeling

## Purpose

Event modeling defines **what happened** in the business using past-tense domain events, aligned to bounded contexts and ubiquitous language.

## Event storming outputs

| Artifact | Description |
| --- | --- |
| Domain events | `OrderPlaced`, `PaymentFailed` |
| Commands | Actions that cause events |
| Policies | Reactions ("when X then Y") |
| Read models | Projections for queries |
| External systems | Upstream/downstream dependencies |

## Naming conventions

- Past tense verbs: `CustomerRegistered`, not `RegisterCustomer`.
- Include aggregate id in payload: `orderId`, `customerId`.
- Version events when semantics change — never overload meaning silently.

## Payload design

```json
{
  "eventType": "OrderPlaced",
  "eventId": "uuid",
  "occurredAt": "2026-06-18T10:00:00Z",
  "aggregateId": "order-123",
  "data": { "customerId": "c-1", "total": 99.50 }
}
```

Prefer **CloudEvents** envelope for cross-platform interoperability.
