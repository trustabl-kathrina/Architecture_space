# 3. How to Use Pub/Sub

## Setup prerequisites

1. Enable `pubsub.googleapis.com` on the GCP project.
2. Create a service account with least-privilege roles (`pubsub.publisher` / `pubsub.subscriber`).
3. Choose region strategy (single region recommended for latency-sensitive pipelines).
4. Define topic and subscription naming convention: `{domain}.{entity}.{env}`.

## Create resources (gcloud)

```bash
# Topic
gcloud pubsub topics create orders.events.prod

# Pull subscription
gcloud pubsub subscriptions create orders.events.prod.processor \
  --topic=orders.events.prod \
  --ack-deadline=60 \
  --message-retention-duration=7d

# Push subscription (Cloud Run)
gcloud pubsub subscriptions create orders.events.prod.notify \
  --topic=orders.events.prod \
  --push-endpoint=https://notify-HASH.run.app/events \
  --push-auth-service-account=pubsub-push@PROJECT.iam.gserviceaccount.com
```

## Publish messages (Python)

```python
from google.cloud import pubsub_v1

publisher = pubsub_v1.PublisherClient()
topic = publisher.topic_path("PROJECT_ID", "orders.events.prod")

# Batching is enabled by default — tune for cost/latency
batch_settings = pubsub_v1.types.BatchSettings(
    max_messages=100, max_bytes=1024 * 1024, max_latency=0.05
)
publisher = pubsub_v1.PublisherClient(batch_settings=batch_settings)

future = publisher.publish(
    topic,
    b'{"orderId": "123"}',
    eventType="OrderCreated",
    ordering_key="customer-42",  # when ordering enabled on subscription
)
future.result()
```

## Subscribe — streaming pull (Python)

```python
from google.cloud import pubsub_v1

subscriber = pubsub_v1.SubscriberClient()
sub_path = subscriber.subscription_path("PROJECT_ID", "orders.events.prod.processor")

flow_control = pubsub_v1.types.FlowControl(
    max_messages=1000, max_bytes=100 * 1024 * 1024
)

def callback(message):
    try:
        process(message.data)
        message.ack()
    except Exception:
        message.nack()

streaming_pull = subscriber.subscribe(
    sub_path, callback=callback, flow_control=flow_control
)
streaming_pull.result()
```

## Subscribe — push (Cloud Run)

Cloud Run receives HTTP POST with Pub/Sub message JSON envelope. Return `200` quickly; defer heavy work to async tasks. Configure invoker permission for Pub/Sub service agent.

## Message attributes and filtering

Attach attributes for routing without parsing payload:

```python
publisher.publish(topic, data, region="eu", severity="high", schema_version="2")
```

Subscription filter example:

```
attributes.region = "eu" AND attributes.severity = "high"
```

## Schemas

1. Create schema (Avro or Protobuf) in Pub/Sub.
2. Attach schema to topic with `ENCODING_BINARY` or `ENCODING_JSON`.
3. Publishers validate on publish; invalid messages rejected.

## IAM patterns

| Role | Scope |
| --- | --- |
| `roles/pubsub.publisher` | Publish to topics |
| `roles/pubsub.subscriber` | Consume from subscriptions |
| `roles/pubsub.admin` | Full control — restrict to platform team |
| Custom | Topic-level `pubsub.topics.publish` on single topic |

Use **workload identity** on GKE and **attached service accounts** on Cloud Run instead of key files.

## Infrastructure as code (Terraform)

```hcl
resource "google_pubsub_topic" "orders" {
  name = "orders.events.prod"
  message_retention_duration = "86400s"
}

resource "google_pubsub_subscription" "processor" {
  name  = "orders.events.prod.processor"
  topic = google_pubsub_topic.orders.id
  ack_deadline_seconds = 60
  enable_exactly_once_delivery = true
}
```

## Observability

- **Metrics:** `pubsub.googleapis.com/topic/send_message_operation_count`, subscription `num_undelivered_messages`, `oldest_unacked_message_age`
- **Alerts:** Backlog age, push latency, dead-letter growth
- **Tracing:** Propagate `traceparent` in attributes; integrate with Cloud Trace

## Operational checklist

- [ ] Batching enabled on publishers for small messages
- [ ] Streaming pull for high-volume consumers
- [ ] Flow control limits set on subscribers
- [ ] Dead-letter topic configured for poison messages
- [ ] Ack deadline aligned with processing time
- [ ] Monitoring on oldest unacked message age
- [ ] Idempotent consumer logic (even with exactly-once)
