# 8. Dataflow Evaluation Criteria

Architect scorecard comparing **Google Cloud Dataflow (Beam)** against Apache Flink, Spark Structured Streaming, and cloud-managed alternatives.

**Rating scale:** 1 (weak) — 5 (excellent)

## Scorecard

| Criterion | Weight | Dataflow | Flink | Spark SS | Notes |
| --- | ---: | ---: | ---: | ---: | --- |
| **Latency** | High | 4 | 5 | 3 | Flink leads sub-second; Spark micro-batch higher baseline |
| **Throughput** | High | 5 | 5 | 5 | All scale horizontally with correct config |
| **Scalability** | High | 5 | 4 | 4 | Dataflow autoscaling managed; Flink/Spark need cluster tuning |
| **Fault tolerance** | High | 5 | 5 | 4 | Checkpointing mature on Flink; Dataflow managed recovery |
| **Exactly-once support** | High | 4 | 5 | 3 | Flink gold standard; Dataflow strong on GCP sinks |
| **Replay capability** | Medium | 3 | 5 | 4 | Replay via source (Pub/Sub retention, GCS); not offset-native |
| **Event-time processing** | High | 5 | 5 | 4 | Beam + Flink first-class; Spark improving |
| **Stateful processing** | High | 4 | 5 | 3 | Flink state largest OSS ecosystem; Streaming Engine helps |
| **Operational complexity** | High | 5 | 2 | 3 | Dataflow minimal ops; Flink cluster expertise required |
| **Cloud portability** | Medium | 2 | 4 | 4 | Beam portable; Dataflow runner GCP-only |
| **Cost** | High | 3 | 4 | 3 | 24/7 streaming adds up; CUDs help; Spark on spot can be cheap |
| **Ecosystem integration** | High | 5* | 4 | 4 | *5 on GCP (BQ, Pub/Sub, Spanner); Flink wins Kafka-native |

## Profile-based recommendation

| Profile | Recommendation |
| --- | --- |
| GCP-standard data platform | **Dataflow default** for stream+batch Beam |
| Existing Flink operations team on K8s | Flink on GKE / managed Flink |
| Databricks enterprise agreement | Spark Structured Streaming |
| Portable Beam, multi-runner | Author Beam; run Dataflow on GCP, Flink elsewhere |
| Simple hourly aggregates | BigQuery scheduled queries first |

## Criterion deep-dives

### Latency

Dataflow typical E2E (Pub/Sub → BQ): **30 s – 2 min** depending on windowing. Flink can achieve lower with custom tuning. Spark SS bounded by micro-batch interval.

### Exactly-once

Dataflow exactly-once streaming mode + supported sinks. Flink transactional Kafka/BQ connectors mature for hybrid estates.

### Operational complexity

Dataflow eliminates cluster patching, slot management, and shuffle node ops — primary TCO advantage for platform teams without stream-processing SREs.

### Cost

24/7 streaming at high `maxNumWorkers` is expensive. Model with [Costing](02.01.02.02.02.05.06_Costing.md). Flink self-managed can be cheaper at very large scale with spot instances — at ops cost.

### Ecosystem integration

Dataflow native I/O for BigQuery, Pub/Sub, Bigtable, Spanner is best-in-class on GCP. Cross-cloud analytics favors portable formats (Avro on GCS) + engine choice.

## Decision tree

```
IF cloud == GCP AND team_accepts_Beam
   AND sink/source_primarily_GCP_native
THEN Dataflow = default_stream_processor
ELIF kafka_centric AND existing_flink_ops
THEN Managed_Flink_or_Flink_on_K8s
ELIF spark_everywhere
THEN Structured_Streaming_on_Dataproc/Databricks
```
